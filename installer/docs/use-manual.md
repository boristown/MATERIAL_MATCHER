# 使用手册（业务操作）

适用版本：1.3.9　对象：业务操作员 / 系统维护员　全程离线可用。
安装/卸载/维护见《安装手册 doc.md》《维护手册 ops.md》，疑难见《faq.md》。

## 1. 登录

1. 在办公电脑浏览器输入服务器地址（安装完成界面会告知，形如 `http://服务器IP:18080`）。
2. 首次登录：用户名 `admin`，密码为安装时设置/自动生成的初始密码（自动生成时由运维人员从服务器 `/etc/material_matcher/secret/admin_password.env` 读取）。
3. 首次登录后系统会强制要求修改密码，请牢记新密码。Win7 电脑若页面异常，先安装介质 `win7/` 目录中的 Firefox ESR。

## 2. 五个主菜单

| 菜单 | 用途 |
|---|---|
| 匹配方案 | 创建/编辑/发布方案（字段映射、阈值、字典） |
| 数据上传 | 上传 SAP 客户物料清单与集团标准码表 |
| 匹配任务 | 发起匹配（STEP1~STEP4 流程与历史任务） |
| 人工复核 | 待人工处理行的 Top5 候选选择与确认 |
| 系统/审计 | 用户管理、审计日志、运行状态 |

## 3. 创建普通匹配方案（推荐流程）

1. 匹配方案 → 新建 → 填写方案名称（如 `A00x 类目名`）。
2. **上传两张模板**：客户物料模板 + 集团码模板（Excel，第一行表头）。系统自动识别 Sheet、表头、全部字段，并给出**一对一**字段映射推荐（不会出现多对多交叉线；可拖拽连线新增、点击连线删除；组合多字段规则为人工扩展功能）。
3. 确认两个关键字段：客户物料编码字段、集团码字段（识别不出来时只需人工选择一次）。
4. 每行映射右侧「值映射」列：点开可为该字段配置字典值（如 `10 → 国产`、`11 → 进口`）。**系统只列出候选值，绝不会自动猜测对应关系**，由人工逐条确认；未在映射表中的值（如 12）会原样保留并转人工确认。
5. 匹配方式每行二选一：**精确匹配 / 智能匹配**。勾选「冲突阻断」（即关键字段）后：该字段得分为 0 时总分保留但禁止自动通过，结果转人工复核，界面标记「关键字段不一致」。
6. 只需设置一个「自动匹配阈值」：达到即自动匹配，未达到转人工。
7. 保存 → 校验 → 发布。每次发布生成新版本号；历史任务永远沿用它执行时的版本，升级方案不影响已跑过的任务。

预置说明：出厂自带 6 个正式方案（A001/A002/A003/A005/A006/A007），其中 5 个子方案已预置「国产进口 10→国产、11→进口」的值映射（权重 0，不改变既有打分，启用时自行调权重即可）；A007 已预置为**跨类目组合方案**（见下节）。全部可人工调整。

## 4. A007 跨类目组合方案（物资类其他）

组合方案本身不配字段，而是引用若干**已发布子方案**并冻结其版本号：

1. 新建/编辑方案 → 方案类型选「组合（跨类目）」。
2. 至少勾选 2 个子方案（默认已含 A001/A002/A003/A005/A006 各冻结版本）。子方案日后升级不影响本组合已发布版本。
3. 匹配时：**SAP 源文件只传 1 个**；集团侧可上传**多份格式完全不同的 Excel**（字段名/数量/Sheet 均可不同），系统按各子方案保存的模板结构自动推荐「子方案→集团文件」对应关系，可人工调整；全部子方案分配完成后才能开始。
4. 运行时各子方案独立计算（各自字段映射/字典/权重/检索），候选汇总统一排序出最终 TopN。
5. 结果追溯：STEP4 与历史任务中可分别下载 SAP 原文件、每个子方案实际使用的集团文件、最终结果 Excel。

## 5. 发起匹配（STEP1~STEP4）

1. 匹配任务 → 新建 → 选择方案（或手工配置）→ 上传 SAP 待匹配文件与集团标准数据。
2. STEP1 确认字段映射；STEP2 计算（十万行规模属正常，耐心等待进度完成）。
3. STEP3 人工复核：计算完成后自动进入复核页——状态标签（全部/已自动匹配/待人工匹配/已人工匹配/未匹配）+ Top1~Top5 横向卡片，可直接选 Top2/Top3 确认或「均不匹配」；筛选与分页全部在服务器端处理，十万行也不卡浏览器。
4. STEP4 输出结果：生成结果 Excel（固定五 Sheet 版式，含匹配构成统计），可下载留档。
5. 历史任务：随时打开查看/恢复，输入文件与结果文件均可重新下载。

## 6. 数据与配置位置（维护人员）

| 内容 | 位置（两种安装方式一致） |
|---|---|
| 数据库/上传件/结果 | `/var/lib/material_matcher/` |
| 配置 | `/etc/material_matcher/`（server.env 端口、storage.env 数据盘） |
| 日志/安装报告 | `/var/log/material_matcher/` |
| 程序 | Docker 方式在容器内；Native 方式在 `/opt/material_matcher/releases/<版本>/`（current 软链） |
| 导出模板后台配置 | `/etc/material_matcher/export_profile.json`（可选；不存在则用内置标准模板；修改后重启服务生效） |
| 定时备份 | `./bk.sh enable [HH:MM]`，保留 14 份 |

## 7. 现场改代码指引（工程师）

介质 `win7/` 目录附 **VSCode 1.82.3**（最后支持 Win7 的官方版本）安装程序，供工程师在自备电脑上离线编辑：

1. 服务器上源码位于 `…/current/app/material_matcher/`（Python）；从服务器拷出到 U 盘 → 在电脑上用 VSCode 修改 → 拷回覆盖同名文件。
2. Python 改动后：`systemctl restart material_matcher`（Native）或 `docker restart material_matcher-app`（Docker）生效；改完务必在测试数据上先跑一遍。
3. 前端改动需重新构建，离线环境无 Node 工具链，建议由原厂构建后走升级介质发布，现场仅做应急 hotfix。
4. 任何改动前先用 `./bk.sh` 手动备份一次，出错可随时恢复。

## 8. 注意事项

- 不要手工修改/删除 `/var/lib/material_matcher` 下的文件。
- 服务器断电重启后服务自动拉起（Docker 方式同时依赖 docker 服务自启，安装器已 enable）。
- 升级 = 用新版本介质重跑 `run.sh`（自动识别升级，数据与密码不动）。
