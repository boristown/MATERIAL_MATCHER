# 物料集团码匹配引擎操作界面设计

> 文档版本：2.2  
> 日期：2026-09-13  
> 状态：Normative  
> 说明：本文是前端业务交互的强制设计基线。详细路由、组件、状态和交互见 `API_UI_DEPLOYMENT_CONTRACT.md` 第 44 章。

## 1. 设计结论

上一版原型存在菜单过多、页面职责重叠、示意图与文字不一致的问题。本版本取消图片生成式 UI 截图作为开发基线，改为**文字契约 + Word 原生线框 + 明确路由**。

核心原则：

- 不以“菜单越多越完整”为目标；
- 不建设独立首页，登录后直接进入“匹配任务”；
- 老板重点关注的人工处理能力属于具体任务的结果工作台；
- 候选对比属于工作台下钻页面；
- 试跑、发布版本属于方案详情；
- 临时文件属于系统设置；
- 任何示意图与本文冲突时，以本文和第 44 章为准。

## 2. 一级导航

左侧一级导航**只能有 4 项**，顺序固定：

```text
匹配任务
匹配方案
数据配置
系统设置
```

禁止出现以下一级菜单：

```text
首页
匹配处理
结果管理
人工复核记录
临时文件管理
集团码目录版本
试跑记录
发布管理
```

上述功能并未删除，而是通过子页面、页签、抽屉或任务详情承载。

## 3. 页面层级

```text
登录
└── 匹配任务（登录后的默认页）
    ├── 新建匹配任务
    ├── 任务详情
    ├── 匹配结果工作台
    └── 候选对比与人工确认

匹配方案
├── 方案列表
└── 方案配置向导
    ├── 客户物料
    ├── 集团码数据
    ├── 分类范围
    ├── 字段对应
    ├── 权重与阈值
    ├── 试跑验证
    └── 发布方案

数据配置
├── 集团码目录
├── 客户数据模板
├── 同义词/字典
└── 索引状态

系统设置
├── 服务状态
├── 存储空间
├── 临时文件
└── 系统诊断
```

## 4. 全局页面框架

最低支持 `1366×768`。

建议尺寸：

- 左侧导航展开 176 px；
- 左侧导航收起 56 px；
- 顶部栏 52 px；
- 内容区内边距 20 px。

顶部栏只保留：

- 产品名称；
- 当前页面名称；
- 服务状态；
- `admin` 菜单。

不设计全局业务搜索框。

线框：

```text
┌──────────────────────────────────────────────────────────────┐
│ 物料集团码匹配引擎     当前页：匹配任务    ●服务正常  admin │
├────────────┬─────────────────────────────────────────────────┤
│ 匹配任务   │                                                 │
│ 匹配方案   │                 页面内容区                      │
│ 数据配置   │                                                 │
│ 系统设置   │                                                 │
└────────────┴─────────────────────────────────────────────────┘
```

## 5. 匹配任务

登录后直接进入任务列表。

任务列表只展示任务本身，不混入临时文件、集团码版本和人工确认等其他管理能力。

固定列：

```text
任务编号
任务名称
匹配方案
客户数据
进度
状态
创建时间
操作
```

操作列只显示 `[查看]`。

任务详情在已完成状态下提供：

```text
[进入匹配结果工作台]
[下载最终结果]
[下载TopN]
[下载人工确认记录]
[下载未匹配清单]
```

## 6. 匹配结果工作台

这是老板反馈中最重要的日常业务页面。

工作台只处理**一个当前任务**，页面必须显示任务名称和任务编号。

### 6.1 汇总区

固定显示：

```text
总物料数
自动匹配
待人工确认
未匹配
已人工确认
```

### 6.2 筛选区

固定控件：

| 编号 | 条件 | 类型 |
|---|---|---|
| F01 | 物料类别 | 多选下拉 |
| F02 | 处理状态 | 多选下拉 |
| F03 | 第一候选分 | 最小值/最大值 |
| F04 | 第二候选分 | 最小值/最大值 |
| F05 | 第一、第二候选分差 | 最小值/最大值 |
| F06 | 关键字段冲突 | 全部/有/无 |
| F07 | 仅看未处理 | 开关 |

快捷筛选固定为：

```text
[90分以上且无冲突]
[80～90分]
[分差<5]
[存在冲突]
[仅待确认]
[清除条件]
```

快捷筛选只是一次性修改 F01～F07，不维护第二套隐藏状态。

### 6.3 结果表

固定列：

```text
选择框
物料编码
物料名称
类别
第一候选集团码
第一候选分
第二候选分
分差
关键字段冲突
状态
操作
```

不显示“处理人”列，因为系统只有固定 `admin`。处理人仅进入审计记录。

行操作：

```text
[查看候选]
[确认第一候选]
[标记未匹配]
```

批量动作只提供：

```text
[批量确认第一候选]
[批量转待人工确认]
[批量标记未匹配]
```

批量确认前必须二次确认并显示影响数量。

### 6.4 老板要求的处理方式

系统必须支持以下连续处理：

```text
先筛 90 分以上且无关键字段冲突
→ 批量确认容易项
→ 已确认记录从“仅看未处理”视图移除
→ 再处理 80～90 分
→ 再处理分差很小的记录
→ 最后处理有关键字段冲突的困难项
```

## 7. 候选对比与人工确认

点击“查看候选”进入当前任务内的候选详情页。

**不采用三个候选横向固定并排作为正式布局。**

原因：真实物料字段可能很多，三列并排会导致文本极度压缩，不能作为严谨开发基线。

默认布局：一次完整展示一个候选，通过 TopN 标签切换：

```text
[候选1 92.0] [候选2 78.0] [候选3 56.0] [更多...]
```

字段对比表固定列：

```text
字段
客户值
集团值
字段得分
权重
关键字段
比较结果
```

比较结果：

```text
一致
接近
冲突
缺失
不参与
```

底部固定动作：

```text
[上一条]
[标记未匹配]
[确认当前候选]
[下一条]
```

人工确认非第一候选时必须记录原第一候选、最终候选、操作时间和 `admin`。

## 8. 匹配方案

一级菜单“匹配方案”只包含：

```text
方案列表
方案配置向导
```

试跑记录、版本发布属于某个方案内部，不占左侧菜单。

七步向导固定：

```text
1 客户物料
2 集团码数据
3 分类范围
4 字段对应
5 权重与阈值
6 试跑验证
7 发布方案
```

## 9. 字段对应 UI

正式开发采用**可编辑映射表**，不强制开发拖拽连线画布。

固定列：

```text
序号
客户字段组合
集团字段组合
组合方式
匹配方式
权重
关键字段
操作
```

支持一对一、一对多、多对一、多对多。

字段组合通过“选择字段 + Tag 顺序”完成。

组合方式：

```text
直接
拼接
第一个有效值
多个比较取最高分
```

权重统一为 `0～100` 整数。

## 10. 权重与阈值

不使用“低/中/高/很高”。

业务 UI 中：

```text
权重：0～100
自动匹配成功阈值：0～100
人工确认下限：0～100
显示相似度系数：0.1～3.0
```

正式判定：

```text
raw_score > success_threshold => 自动匹配
review_threshold < raw_score <= success_threshold => 待人工确认
raw_score <= review_threshold => 未匹配
```

显示分不得参与判定。

## 11. 数据配置

只使用页签：

```text
集团码目录 | 客户数据模板 | 同义词/字典 | 索引状态
```

普通业务模式不展示 BBQ、HNSW、向量维度等技术参数。

## 12. 系统设置

只使用页签：

```text
服务状态 | 存储空间 | 临时文件 | 系统诊断
```

临时文件不得单独占一级导航。

## 13. 实现红线

以下任一项出现即视为 UI 偏离设计：

1. 左侧超过 4 个一级菜单；
2. 登录后进入独立首页；
3. 人工确认成为一级菜单；
4. 临时文件成为一级菜单；
5. 任务列表混入临时文件/目录版本管理；
6. 字段映射只有复杂连线画布，没有表格方式；
7. 候选详情只能三列横排；
8. 工作台缺少第二候选分或分差筛选；
9. 工作台不能批量确认第一候选；
10. 快捷筛选和正式筛选使用两套不一致的状态。
