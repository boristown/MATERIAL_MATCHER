# 物料集团码匹配引擎操作界面设计

> 文档版本：2.0  
> 日期：2026-09-13  
> 目标：将界面设计收敛为可直接指导开发和验收的交互规范，重点满足业务负责人提出的“高可视化、强筛选、批量处理、快速人工确认”。

## 1. 设计结论

界面不以“目录越多越完整”为目标，而以业务人员完成任务的路径最短、认知成本最低为目标。

日常使用最关键的两类操作是：

1. 配置阶段：数据上传、字段对应、数字权重、阈值、分类范围、试跑；
2. 匹配完成后：筛选结果、查看多个候选、批量确认容易项、逐步处理困难项。

因此一级导航固定为 6 项：

```text
首页
匹配方案
数据管理
匹配任务
匹配处理
系统设置
```

以下内容不再占独立一级目录：

- 方案列表、配置向导、试跑记录、发布版本：放入“匹配方案”；
- 集团码目录、客户样表、字典、索引：放入“数据管理”；
- 结果导出：放入“匹配任务”；
- 待复核、已处理、人工确认记录：放入“匹配处理”；
- 临时文件、磁盘空间、端口、诊断：放入“系统设置”。

## 2. 总体布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 物料集团码匹配引擎 / 全局搜索                  admin / 状态   │
├──────────┬───────────────────────────────────────────────────┤
│ 首页     │                                                   │
│ 匹配方案 │                   当前页面                        │
│ 数据管理 │                                                   │
│ 匹配任务 │                                                   │
│ 匹配处理 │                                                   │
│ 系统设置 │                                                   │
└──────────┴───────────────────────────────────────────────────┘
```

最低支持 1366×768。左侧导航固定，表格字段过多时允许横向滚动并固定关键列。

## 3. 匹配方案

内部页签：

```text
方案列表 | 新建/编辑方案 | 试跑记录 | 发布版本
```

新建/编辑方案使用 7 步向导：

```text
① 客户物料
→ ② 集团码数据
→ ③ 分类范围
→ ④ 字段对应
→ ⑤ 权重与阈值
→ ⑥ 试跑验证
→ ⑦ 发布方案
```

字段对应页必须支持：

- 一对一、一对多、多对一、多对多；
- 字段拼接顺序；
- 匹配方式；
- 0～100 数字权重；
- 关键字段；
- 来源/目标样例值；
- 自动推荐关系；
- 修改、删除和复制关系。

权重统一使用数字，不使用“低/中/高”等主观词。

## 4. 匹配任务

匹配任务页面只负责：

- 新建任务；
- 查看执行进度；
- 暂停、继续、取消；
- 查看失败原因；
- 打开任务结果；
- 导出最终结果、TopN、人工确认记录、未匹配清单。

不再单独建设“结果管理”一级目录。

## 5. 匹配处理工作台（核心页面）

这是根据业务负责人反馈必须重点实现的核心页面。

### 5.1 顶部统计

显示：

- 总物料数；
- 已自动匹配；
- 待人工复核；
- 未匹配；
- 已人工确认。

### 5.2 筛选条件

至少包括：

- 物料类别；
- 处理状态；
- 第一候选分数范围；
- 第二候选分数范围；
- 第一名与第二名分差；
- 是否存在关键字段冲突；
- 是否已人工处理。

快捷筛选：

```text
90分以上
80～90分
分差小于5
存在关键字段冲突
仅待复核
仅看未处理
```

业务负责人提出的处理方式必须直接支持：

```text
先筛高分且无冲突记录
→ 批量确认
→ 已确认记录自动退出未处理列表
→ 再处理80～90分
→ 再处理低分或分差很小的困难记录
```

### 5.3 表格字段

| 字段 | 说明 |
|---|---|
| 物料编码 | 客户物料唯一标识 |
| 物料名称 | 客户物料名称 |
| 类别 | 当前业务分类 |
| 第一候选集团码 | 当前最高候选 |
| 第一候选分 | 0～100 |
| 第二候选分 | 0～100 |
| 分差 | 第一候选分 - 第二候选分 |
| 关键字段冲突 | 是/否 |
| 状态 | 自动匹配/待复核/未匹配/人工确认 |
| 操作 | 查看候选/确认第一候选/标记未匹配 |

### 5.4 批量操作

支持：

- 批量确认第一候选；
- 批量转人工复核；
- 批量标记未匹配。

批量确认前必须二次确认并展示影响记录数。

## 6. 候选对比与人工确认

点击“查看候选”后进入详情页或大尺寸抽屉。

至少展示 Top3，允许扩展至 TopN。

每个候选必须显示：

- 集团码；
- 集团物料名称；
- 总相似度；
- 字段名称；
- 来源值；
- 候选值；
- 字段得分；
- 是否关键字段；
- 是否冲突；
- 推荐理由。

允许操作：

- 确认候选1；
- 确认候选2；
- 确认其他候选；
- 标记未匹配；
- 上一条/下一条待处理记录。

人工确认后必须保存操作者、时间、原候选和最终选择，并纳入后续评测样本。

## 7. 数据管理

内部页签：

```text
集团码目录 | 客户样表 | 字典 | 索引状态
```

普通业务模式不展示 BBQ、向量维度、HNSW 等技术参数，只展示数据版本、记录数、索引状态和构建进度。

## 8. 系统设置

内部页签：

```text
服务状态 | 存储空间 | 临时文件 | 系统诊断
```

临时文件不再单独占一级目录。

支持按任务、时间和类型清理临时文件，但正式集团码目录、正式索引、正式结果和已发布方案不得进入清理范围。

## 9. 原型图取舍

设计书保留 3 类核心原型：

1. 方案配置向导：定义字段映射、数字权重和阈值配置；
2. 匹配处理工作台：定义筛选、分段处理和批量确认；
3. 候选对比与人工确认：定义单条记录的多候选对比和最终选择。

“任务与结果管理”原型不作为核心定稿图。其有效功能分别并入“匹配任务”和“系统设置”，避免页面职责过重。

原型图是交互和信息结构约束，不是像素级视觉稿。开发可调整颜色和留白，但不得改变核心字段和业务动作。

## 10. 验收要求

至少验证：

1. 普通业务人员可不查看技术配置文件完成一套方案；
2. 可一键筛选 90 分以上记录；
3. 可筛选第一、第二候选分差小于 5 的高风险记录；
4. 可批量确认第一候选；
5. 已处理记录能自动从“未处理”视图移除；
6. 单条记录能查看多个候选及字段级得分；
7. 人工选择非第一候选时完整留痕；
8. 1366×768 下关键按钮和核心字段可正常操作；
9. 同一套 UI 能适配不同客户，不允许前端出现客户专属判断。
