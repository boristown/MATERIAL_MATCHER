# 物料集团码智能匹配平台操作界面设计

> 文档版本：3.0  
> 日期：2026-09-16  
> 状态：Normative  
> 说明：本文是前端业务交互的强制设计基线，与 `DEVELOPMENT_DESIGN.md` v3.0 保持一致。旧版“五步统一向导”不再作为侧栏和一级页面结构；其中“选择数据/确认规则”保留为 STEP1 内部子流程。

---

## 1. 最终交互目标

业务用户进入系统后，只需要理解一条四步主线：

```text
STEP 1 · 方案与配置
→ STEP 2 · 匹配计算
→ STEP 3 · 人工调整
→ STEP 4 · 输出结果
```

支撑入口：

```text
基础数据
系统设置
```

产品必须做到：

- 用户清楚自己当前在哪一步；
- 每一步首屏都告诉用户“当前是否有可操作数据”和“下一步做什么”；
- 技术 ID、索引算法、物理文件等实现细节不抢占业务首屏；
- 页面上的状态和统计全部来自真实后端；
- 浏览器刷新、重新登录后可以恢复任务真实状态；
- 不因为页面重构破坏任务快照、目录版本和人工审计。

## 2. 全局布局

### 2.1 侧栏

侧栏固定显示：

```text
[SVG Logo] 集团码匹配

1 STEP 1 · 方案与配置
  字段映射 · 过滤 · 阈值

2 STEP 2 · 匹配计算
  实时进度 · 中间结果

3 STEP 3 · 人工调整
  复核 · 重判 · 候选对比

4 STEP 4 · 输出结果
  匹配摘要 · Excel 下载

基础数据
系统设置
```

要求：

- 不显示 `MATERIAL_MATCHER` 英文副标题；
- 不显示“支撑功能”标题；
- 当前步骤高亮；
- STEP1～STEP4 使用连续流程视觉；
- “基础数据/系统设置”与主流程保持适度间距，但不做与主流程同等级编号；
- Logo 使用矢量 SVG，在不同缩放比例保持清晰。

### 2.2 顶部栏

左侧：

```text
物料集团码智能匹配平台
```

右侧：

```text
当前用户 + 角色 + 退出
```

身份信息、Tag、按钮在同一基线，不允许出现明显上下错位。

### 2.3 主内容区

统一使用：

- 浅灰页面背景；
- 白色卡片；
- 统一圆角和边框；
- 蓝色主操作；
- 绿色成功；
- 红色失败/危险；
- 低对比灰色辅助信息。

任何页面不得因为空数据只留下大面积空白，必须给出有意义的空状态。

## 3. STEP1 · 方案与配置

### 3.1 页面职责

STEP1 同时承担：

- 匹配方案模板管理；
- 基于已发布方案创建任务；
- 新建/编辑方案规则。

但“编辑方案”和“创建任务”必须是两个清晰模式，不能把两种操作混在一个页面。

### 3.2 方案列表

卡片至少显示：

```text
方案名称
已发布版本
是否有草稿
更新时间
```

操作：

```text
[用此方案建任务] [编辑] [版本] [重命名] [删除(有权限)]
```

布局要求：

- 4～5 个按钮不得超出卡片；
- 长方案名称不得挤出按钮；
- 按钮可以自动换行；
- 卡片高度可以随内容自然变化；
- 不允许通过固定宽度把操作按钮裁掉。

### 3.3 方案编辑模式

点击 `[编辑]`：

页面标题明确显示：

```text
编辑匹配方案
```

只展示规则配置：

```text
字段映射
匹配范围
字段组合
匹配方式
权重
关键字段
判定阈值
TopN
高级数据处理
草稿/发布
```

不得出现：

```text
正式任务名称
正式 Source 数据上传
开始匹配/启动任务
```

### 3.4 用方案建任务模式

点击 `[用此方案建任务]`：

页面标题明确显示：

```text
创建匹配任务
```

默认载入最新已发布方案，并展示只读摘要：

```text
方案名称
方案版本
匹配范围
参与字段数
自动匹配阈值
人工确认区间
TopN
```

用户只需完成：

```text
任务名称
上传/选择本次客户物料数据
确认目标集团码目录版本
确认规则摘要
[启动匹配任务]
```

不默认展开完整方案编辑器。

如果允许本次临时修改，应放在“本任务高级设置”中，并明确：

```text
仅影响本任务，不修改原方案
```

### 3.5 新建方案

新建方案以规则维护为目标，可通过样表识别字段。完成配置后先形成草稿，用户主动发布后才成为可复用正式版本。

---

## 4. STEP2 · 匹配计算

### 4.1 页面结构

```text
页面标题 + 新建匹配任务

[当前运行任务操作框 / 无运行任务空状态]

[历史任务与草稿列表]
```

顶部运行框是首屏重点，历史表格视觉层级降低。

### 4.2 有运行任务

显示：

```text
任务名称
当前阶段
总体百分比
已处理 / 总行数
已匹配集团码
待人工确认
未匹配（可获得时）
吞吐
已运行时间
预计剩余时间
预计完成时间
[进入实时看板]
```

### 4.3 无运行任务

显示：

```text
无正在进行的任务
请通过 STEP 1 选择方案、上传数据并启动匹配任务。
[前往 STEP 1 配置并启动]
```

### 4.4 业务阶段文案

普通用户只看到：

```text
数据准备
索引/目标数据准备
候选召回
精细评分
结果整理
完成
```

BBQ、HNSW、SIMD、量化位宽等只进入管理员技术信息。

### 4.5 实时中间结果

页面可展示最近已处理记录和当前统计，但必须标识为“中间结果/实时预览”，不能与最终结果混淆。

---

## 5. STEP3 · 人工调整

### 5.1 页面结构

```text
页面标题

[人工处理操作台]

[可处理/历史任务列表]
```

### 5.2 状态一：有可人工处理任务

顶部操作台显示：

```text
可进行人工处理
任务：xxx
待确认：N
自动匹配：N
未匹配：N
[进入人工调整]
```

最近/当前可处理任务优先。

### 5.3 状态二：STEP2 正在计算

如果有运行任务但尚无人工处理数据：

```text
正在等待 STEP 2 计算完成
任务：xxx
当前进度：xx%
```

可以提供 `[查看计算进度]`，不得显示“进入人工调整”。

### 5.4 状态三：没有任何可处理数据

显示：

```text
当前没有计算完成的数据，请先启动 STEP 2 的数据计算。
[前往 STEP 2] [前往 STEP 1]
```

### 5.5 具体人工工作台

默认仅显示未处理 REVIEW。

顶部统计：

```text
待确认 | 已确认 | 自动匹配 | 未匹配
```

筛选：

```text
分数区间
分差区间
关键字段冲突
分类
状态
```

主表：

```text
物料编码
物料名称/描述
第一候选集团码
第一候选分
第二候选分
分差
关键字段冲突
操作
```

操作：

```text
[查看候选]
[确认第一候选]
[标记未匹配]
```

批量操作：

```text
[批量确认第一候选]
[批量标记未匹配]
```

### 5.6 候选详情

候选详情优先使用右侧抽屉/局部工作区，不离开当前人工处理上下文。

展示每个候选的字段级：

```text
客户值
集团值
字段得分
权重
冲突状态
```

## 6. STEP4 · 输出结果

### 6.1 页面结构

```text
页面标题

[最新结果工作台]

[历史结果列表]
```

最新结果卡是首屏核心，不能继续只展示一个普通任务表。

### 6.2 已有完成结果

顶部显示最近一次正式结果：

```text
任务名称
完成时间
总行数
自动匹配数
人工确认数
未匹配数
仍待确认数（如有）
```

提供简洁结果预览和主操作：

```text
[查看完整结果]
[下载 Excel]
```

### 6.3 正在生成/等待前一步

如果最新任务处于 STEP2/STEP3 或结果正在生成：

```text
结果尚未准备完成
当前任务：xxx
当前阶段：xxx
```

根据阶段提供前往 STEP2/STEP3 的入口。

### 6.4 尚无任何结果

显示：

```text
尚无可下载结果
请先启动匹配任务并完成必要的人工调整。
```

### 6.5 历史结果

历史列表保留：

- 查看；
- 下载；
- 准确率验收。

但列表不抢占顶部最新结果的视觉重点。

## 7. 基础数据

### 7.1 页面原则

业务用户首先只需要理解两个概念：

```text
集团码目录
业务字典
```

### 7.2 集团码目录

显示业务字段：

```text
目录名称
版本
状态
是否当前
创建时间
操作
```

主要操作：

```text
上传新目录
上传新版本
激活版本
查看版本
```

普通页面不突出 version_id、file_id 等技术 ID。

### 7.3 业务字典

显示：

```text
字典名称
最新版本
用途/映射条目
更新时间
操作
```

主要操作：

```text
新建业务字典
维护条目
发布新版本
查看历史
```

### 7.4 文件资产与向量索引

二者属于技术资产。

处理方式：

- 默认不与业务数据同级展示；
- 如运维确有需要，放入“高级信息/技术信息”；
- 默认折叠；
- 可限制管理员可见；
- 不删除后端文件、索引和诊断 API。

普通业务界面不得默认显示：

```text
File ID
Index ID
embedded_bbq_flat_v2
绝对物理路径
量化算法内部名
```

## 8. 系统设置

### 8.1 页面结构

```text
系统设置标题
[当前身份] [修改我的密码] [刷新状态]

运行环境
账号与权限
其他管理员/运维信息
```

顶部三个区域必须在同一视觉基线。

### 8.2 运行环境

可展示：

```text
版本
数据目录
向量索引目录
角色模型
当前账号
服务状态
```

### 8.3 账号与权限

管理员界面：

```text
用户名
角色
启用
需改密
更新时间
操作
```

支持：

```text
创建账号
修改角色
启停账号
重置密码
修改自己的密码
```

所有操作使用真实后端接口。

### 8.4 对齐要求

- Tag 与 Button 高度协调；
- Select/Switch/文本垂直居中；
- 长时间戳使用人类可读格式；
- 控件不得因表格列宽变化发生明显上下错位；
- 1366×768 和 1920×1080 均需检查。

---

## 9. 全局状态设计

每个正式页面都必须设计以下状态：

```text
Loading
正常有数据
空数据
无权限
后端失败
前置步骤未完成
数据生成中
```

禁止：

- 白屏；
- 大面积空白但不给解释；
- 用 0 行表格代替业务空状态；
- 后端失败时仍展示“已完成”；
- 前一步未完成却显示可执行下一步的主按钮。

---

## 10. 前后端接入要求

UI 出现的数据必须真实接入后端。

重点检查：

- 方案 CRUD/版本/发布/回滚；
- 任务草稿；
- Source 上传；
- 目录版本；
- 任务启动；
- progress/live-results；
- workbench summary/items/candidates；
- confirm/reject/batch；
- finalize/exports/download；
- 用户、角色、密码和状态；
- 集团码目录和业务字典。

页面不得通过前端数组伪造“任务、结果、统计值、下载文件”。

---

## 11. 浏览器最低版本与升级提示

正式最低版本：

```text
Firefox >= 79
Chrome >= 87
```

不满足版本时，在 Vue 主应用加载前显示独立提示页面：

```text
浏览器版本过低
请使用 Firefox ≥79
```

或：

```text
浏览器版本过低
请使用 Chrome ≥87
```

该提示页必须能在 Firefox 47 这类旧浏览器中独立工作，不能依赖 Vue/Element Plus。

## 12. 多 Agent 页面边界

页面级改造应保持：

```text
STEP1: ProfilesView.vue / TaskWorkspace.vue
STEP2: TasksView.vue
STEP3: ReviewView.vue + review.css
STEP4: ResultsView.vue + results.css
基础数据: DataView.vue
系统设置: SystemView.vue
```

页面 Agent 默认不修改：

```text
App.vue
router.ts
api.ts
main.ts
styles.css
vite.config.ts
package.json
```

这样可以让多个 Agent 同时开发不同页面而不互相覆盖。

---

## 13. UI 验收清单

正式合并前至少验证：

1. 方案卡片按钮在长名称和窄屏下不溢出；
2. “编辑”和“用此方案建任务”进入不同语义页面；
3. STEP2 有运行/无运行状态正确；
4. STEP3 三种顶部状态正确；
5. STEP4 能展示最新结果、预览和真实下载；
6. 基础数据业务资产优先，技术资产已降级；
7. 系统设置顶部与表格控件对齐；
8. 所有页面刷新后仍从后端恢复真实状态；
9. reviewer/viewer 不出现无权执行的有效操作；
10. Firefox <79 / Chrome <87 显示升级提示。

---

## 14. 实现红线

以下任一项视为偏离 v3.0 UI 设计：

1. STEP2/STEP3/STEP4 又合并成一个 `TasksView + mode` 大页面；
2. 方案编辑页面同时出现任务启动区；
3. 创建任务页面默认暴露完整方案编辑器；
4. STEP3 只有任务表，没有状态化操作台；
5. STEP3 在 STEP2 未完成时误导用户可以人工确认；
6. STEP4 只有历史任务表，没有最新结果工作台；
7. 最终结果没有突出真实 Excel 下载；
8. 文件资产、向量索引与集团码目录处于同一业务层级；
9. 普通用户首屏出现大量技术 ID、算法名、物理路径；
10. 页面展示的数据没有真实后端来源；
11. 低版本浏览器直接白屏而不是升级提示；
12. 为修一个页面随意修改全局共享文件导致其他 Agent 冲突。
