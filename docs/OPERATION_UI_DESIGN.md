# 物料集团码匹配引擎操作界面设计

> 文档版本：2.5  
> 日期：2026-09-13  
> 状态：Normative  
> 说明：本文是前端业务交互的强制设计基线。

## 1. 最终交互目标

最终 UI 不要求业务人员先理解“方案、目录、索引、任务”等系统对象。一次匹配必须沿一条连续主线完成：

```text
1 选择数据
→ 2 确认匹配规则
→ 3 比对计算
→ 4 人工处理
→ 5 生成结果
```

点击“新建匹配任务”后，用户始终处于同一个任务工作区，不要求中途跳转到其他一级菜单。

核心原则：

- 普通用户只需要理解“拿哪批客户物料，和哪套集团码数据进行匹配”；
- 已有匹配方案只是可选模板，不是任务运行的前置条件；
- 比对、人工处理、结果生成都保持同一任务上下文；
- 刷新、重新登录或中途离开后，点击“继续”恢复上次阶段；
- 技术细节通过高级区域承载，不干扰普通业务流程。

## 2. 一级导航

一级导航固定为 4 项：

```text
匹配任务
匹配方案
基础数据
系统设置
```

定位：

- **匹配任务**：普通业务人员的主要入口，完成一次完整匹配；
- **匹配方案**：可复用的规则模板库；
- **基础数据**：集团码目录、客户数据模板、同义词/字典和索引状态；
- **系统设置**：服务、存储、临时文件、诊断。

禁止新增“人工复核”“结果管理”“临时文件管理”“索引管理”等一级菜单。

## 3. 匹配任务列表

登录后直接进入匹配任务列表。

顶部：

```text
[新建匹配任务]   任务名称/编号   状态   日期范围   [查询]
```

固定列：

```text
任务编号
任务名称
当前阶段
进度
状态
创建时间
操作
```

当前阶段：

```text
选择数据
确认规则
比对计算
人工处理
生成结果
```

未完成任务操作为 `[继续]`，已完成任务为 `[查看]`。

## 4. 新建匹配任务：5 步统一向导

顶部阶段条始终显示：

```text
① 选择数据 ─ ② 确认匹配规则 ─ ③ 比对计算 ─ ④ 人工处理 ─ ⑤ 生成结果
```

### 4.1 第 1 步：选择数据

只要求：

1. 任务名称；
2. 客户物料数据；
3. 集团码数据版本；
4. 可选：已有匹配方案模板。

已有方案不是必填。未选择时，系统根据样表自动识别字段，并在第 2 步给出推荐配置。

按钮：

```text
[取消]                                  [下一步：确认匹配规则]
```

### 4.2 第 2 步：确认匹配规则

页面只保留四个业务区域：

```text
A. 匹配范围
B. 字段对应与重要程度
C. 判定阈值
D. 高级处理（默认折叠）
```

A. 匹配范围：全库匹配 / 同组匹配 / 分类映射匹配。

B. 字段对应使用可编辑表格：

```text
客户字段组合
集团字段组合
组合方式
匹配方式
权重 0～100
关键字段
数据处理
```

C. 判定阈值：

```text
自动匹配成功阈值
启用人工确认
人工确认下限
前 N 名候选
```

D. 高级处理：空值、同义词、字段处理流水线、尺寸/标准号、数值容差等。默认折叠。

页面固定显示配置摘要，例如：

```text
参与字段：6 个
总权重：420（系统自动归一）
自动匹配阈值：88 分
人工确认区间：75～88 分
候选输出：Top 5
```

辅助按钮：

```text
[试算100条]
[保存本次规则为方案]
```

保存为方案不是继续任务的前置条件。

主按钮：

```text
[上一步]                             [下一步：开始比对]
```

### 4.3 第 3 步：比对计算

开始前显示：

```text
客户物料数量
集团物料数量
是否需要首次构建索引
预计耗时
预计新增磁盘
```

如果需要首次构建索引，应将额外时间单独提示。

主按钮：

```text
[开始比对]
```

运行过程中普通用户只看到：

```text
✓ 数据准备
✓ 向量化处理
● 候选比对
○ 精细评分
○ 结果整理
```

不得在普通界面展示 BBQ、HNSW、SIMD、量化位宽等底层名词。

同时显示总体进度、已处理数量、总数量、已运行时间、预计剩余时间和 `[取消任务]`。

计算完成后：

- 有待人工确认记录：自动进入第 4 步；
- 无待人工确认记录：显示“无需人工处理”，允许直接进入第 5 步。

### 4.4 第 4 步：人工处理

默认只显示**待人工确认**记录。

首屏统计：

```text
待确认 | 已确认 | 未匹配 | 自动匹配
```

快捷入口：

```text
[高分且无冲突]
[80～90分]
[分差<5]
[存在关键字段冲突]
[全部待确认]
```

高级条件放入“更多筛选”，默认折叠。

主表固定列：

```text
选择
物料编码
物料名称
第一候选集团码
第一候选分
第二候选分
分差
关键字段冲突
操作
```

行操作：

```text
[查看候选]
[确认第一候选]
[标记未匹配]
```

批量操作只保留：

```text
[批量确认第一候选]
[批量标记未匹配]
```

不保留“批量转待人工确认”，因为当前页面本身就是待人工确认工作台。

底部主按钮：

```text
[生成最终结果]
```

若仍存在未处理的 REVIEW 记录，必须二次确认；继续生成时这些记录的最终集团码保持为空。

### 4.5 候选详情抽屉

点击“查看候选”在右侧打开大尺寸抽屉，不离开当前人工处理页面。

候选标签：

```text
候选1 92.0分 | 候选2 78.0分 | 候选3 56.0分 | 更多
```

一次完整展示一个候选，字段表：

```text
字段
客户值
集团值
字段得分
权重
结果
```

底部：

```text
[标记未匹配]                         [确认当前候选]
```

确认后主表立即刷新，并自动定位到下一条待处理记录；当前筛选范围处理完毕时自动关闭抽屉并提示完成。

### 4.6 第 5 步：生成结果

进入本阶段后系统自动生成最终结果文件，不要求进入独立“结果管理”。

显示：

```text
总物料数
自动匹配数
人工确认数
未匹配数
仍待确认数
```

主按钮必须是：

```text
[下载最终结果 Excel]
```

次要导出放入“其他导出”：

- TopN 候选；
- 人工确认记录；
- 未匹配清单。

如果任务使用临时规则，可在此选择：

```text
[保存本次规则为可复用方案]
```

但不影响结果下载。

## 5. 匹配方案的定位

“匹配方案”只作为可复用模板库，不再承担“先配置、发布、再回到任务创建”的强制路径。

方案编辑必须与任务第 2 步复用同一套规则编辑组件，禁止开发两套配置界面。

## 6. 基础数据

页签：

```text
集团码目录 | 客户数据模板 | 同义词/字典 | 索引状态
```

日常匹配不要求业务人员进入该页面。

## 7. 系统设置

页签：

```text
服务状态 | 存储空间 | 临时文件 | 系统诊断
```

## 8. 状态恢复要求

- 第 1、2 步自动保存任务草稿；
- 比对计算刷新后从后端恢复真实进度；
- 人工处理筛选条件写入 URL query；
- 候选抽屉关闭后保持筛选、页码和滚动位置；
- 重新登录后从任务列表点击“继续”恢复上次阶段；
- 结果生成失败允许单独重试，不重新执行匹配。

## 9. 实现红线

以下任一项出现即视为偏离设计：

1. 普通用户必须跳出“匹配任务”才能完成一次匹配；
2. 强制先发布匹配方案才能运行任务；
3. 任务工作区没有五步阶段条；
4. 高级数据处理默认全部展开；
5. 计算过程向普通用户展示 BBQ/HNSW/SIMD 等底层术语；
6. 人工处理默认混入大量已自动匹配/已处理记录；
7. 人工处理保留无业务价值的多余批量动作；
8. 查看候选必须跳转到独立页面，导致工作台上下文丢失；
9. 人工处理完成后还必须进入独立“结果管理”页面；
10. 最终结果页没有突出“下载最终结果 Excel”；
11. 任务规则编辑和匹配方案编辑使用两套不同组件。
