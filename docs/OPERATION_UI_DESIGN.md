# 物料集团码智能匹配平台操作界面设计

> 文档版本：3.1  
> 日期：2026-09-16  
> 状态：Normative  
> 说明：本文是前端业务交互的强制设计基线，与 `DEVELOPMENT_DESIGN.md` v3.0 保持一致。旧版“五步统一向导”和 `STEP 1/2/3/4` 英文编号不再作为用户可见侧栏、页面标题、空状态或跳转文案。

---

## 1. 最终交互目标

业务用户进入系统后，只需要理解一条四步主线：

```text
第一步 · 数据上传
→ 第二步 · 进度监控
→ 第三步 · 人工调整
→ 第四步 · 输出结果
```

支撑入口：

```text
业务字典
系统设置
```

产品必须做到：

- 用户清楚自己当前在哪一步；
- 每一步首屏都告诉用户“当前是否有可操作数据”和“下一步做什么”；
- 技术 ID、索引算法、物理文件等实现细节不抢占业务首屏；
- 页面上的状态和统计全部来自真实后端；
- 浏览器刷新、重新登录后可以恢复任务真实状态；
- 不因为页面重构破坏任务快照、目录版本和人工审计。

## 2. 全局布局

### 2.1 侧栏

侧栏固定显示：

```text
[小罡 AI 品牌 Logo] 小罡 AI
                    物料智能匹配

1 第一部 · 数据上传
  上传源 Excel 与目标集团码 Excel

2 第二步 · 进度监控
  查看任务进度与实时处理情况

3 第三步 · 人工调整
  集中处理需要人工确认的记录

4 第四步 · 输出结果
  查看结果摘要并下载 Excel

业务字典
系统设置
```

> 注：正式实现中的第一项文案必须写作“第一步 · 数据上传”，上方代码块中的编号仅表示侧栏序号，不属于标题文本。

要求：

- 左上角统一使用现有“小罡 AI”品牌资产，不再使用集团码匹配自制 Logo；
- 平台业务名称仍为“物料集团码智能匹配平台”；
- 不显示 `MATERIAL_MATCHER` 英文副标题；
- 不显示“支撑功能”标题；
- 当前步骤高亮；
- 四个步骤使用连续流程视觉；
- “业务字典/系统设置”与主流程保持适度间距，但不做与主流程同等级编号；
- Logo 使用矢量 SVG，在不同缩放比例保持清晰。

### 2.2 顶部栏

左侧：

```text
物料集团码智能匹配平台
```

右侧：

```text
当前用户 + 角色 + 退出
```

身份信息、Tag、按钮在同一基线，不允许出现明显上下错位。

### 2.3 主内容区

统一使用：

- 浅灰页面背景；
- 白色卡片；
- 统一圆角和边框；
- 蓝色主操作；
- 绿色成功；
- 红色失败/危险；
- 低对比灰色辅助信息。

任何页面不得因为空数据只留下大面积空白，必须给出有意义的空状态。

## 3. 第一步 · 数据上传

### 3.1 页面职责

第一步面向业务用户的首要职责是创建/恢复一次匹配任务，并直接处理本次数据：

```text
任务名称
源 Excel
目标集团码 Excel
字段映射/规则
阈值与必要的数据处理设置
```

匹配方案仍可作为复用规则模板存在，但不得要求普通用户先去“基础数据”维护集团码目录后才能创建任务。

### 3.2 数据上传

默认业务路径：

```text
上传源 Excel
上传目标集团码 Excel
确认字段识别与映射
确认匹配规则摘要
进入下一步
```

平台可以在后台自动形成文件记录、目标数据版本和向量索引，但普通用户不需要理解这些技术对象。

### 3.3 方案编辑能力

如用户进入方案编辑模式，页面只展示可复用规则配置：

```text
字段映射
匹配范围
字段组合
匹配方式
权重
关键字段
判定阈值
TopN
高级数据处理
草稿/发布
```

方案编辑和正式任务数据上传必须保持清晰边界。

### 3.4 本任务规则

如果允许本次临时修改，应放在“本任务高级设置”中，并明确：

```text
仅影响本任务，不修改原方案
```

### 3.5 草稿恢复

任务名称、源文件、目标文件、字段映射、matcher、权重、关键字段、阈值和数据处理配置必须由后端草稿持久化。刷新、关闭页面或重新登录后返回原任务 URL，应恢复真实状态。

---

## 4. 第二步 · 进度监控

### 4.1 页面结构

```text
页面标题 + 新建匹配任务

[当前运行任务操作框 / 无运行任务空状态]

[历史任务与草稿列表]
```

顶部运行框是首屏重点，历史表格视觉层级降低。

### 4.2 有运行任务

显示：

```text
任务名称
当前阶段
总体百分比
已处理 / 总行数
已匹配集团码
待人工确认
未匹配（可获得时）
吞吐
已运行时间
预计剩余时间
预计完成时间
[进入实时看板]
```

### 4.3 无运行任务

显示：

```text
无正在进行的任务
请先在“第一步 · 数据上传”中准备数据并启动匹配任务。
[前往第一步 · 数据上传]
```

### 4.4 业务阶段文案

普通用户只看到：

```text
数据准备
目标数据准备
候选召回
精细评分
结果整理
完成
```

BBQ、HNSW、SIMD、量化位宽等只进入管理员高级技术信息。

### 4.5 实时中间结果

页面可展示最近已处理记录和当前统计，但必须标识为“中间结果/实时预览”，不能与最终结果混淆。

---

## 5. 第三步 · 人工调整

### 5.1 页面结构

```text
页面标题

[人工处理操作台]

[可处理/历史任务列表]
```

### 5.2 状态一：有可人工处理任务

顶部操作台显示：

```text
可进行人工处理
任务：xxx
待确认：N
自动匹配：N
未匹配：N
[进入人工调整]
```

最近/当前可处理任务优先。

### 5.3 状态二：仍在计算

如果有运行任务但尚无人工处理数据：

```text
正在等待“第二步 · 进度监控”中的计算完成
任务：xxx
当前进度：xx%
```

可以提供 `[查看进度监控]`，不得显示“进入人工调整”。

### 5.4 状态三：没有任何可处理数据

显示：

```text
当前没有计算完成的数据，请先完成“第二步 · 进度监控”对应任务的数据计算。
[前往第二步 · 进度监控] [前往第一步 · 数据上传]
```

### 5.5 具体人工工作台

默认仅显示未处理 REVIEW。

顶部统计：

```text
待确认 | 已确认 | 自动匹配 | 未匹配
```

筛选：

```text
分数区间
分差区间
关键字段冲突
分类
状态
```

主表：

```text
物料编码
物料名称/描述
第一候选集团码
第一候选分
第二候选分
分差
关键字段冲突
操作
```

操作：

```text
[查看候选]
[确认第一候选]
[标记未匹配]
```

批量操作：

```text
[批量确认第一候选]
[批量标记未匹配]
```

### 5.6 候选详情

候选详情优先使用右侧抽屉/局部工作区，不离开当前人工处理上下文。

展示每个候选的字段级：

```text
客户值
集团值
字段得分
权重
冲突状态
```

## 6. 第四步 · 输出结果

### 6.1 页面结构

```text
页面标题

[最新结果工作台]

[历史结果列表]
```

最新结果卡是首屏核心，不能继续只展示一个普通任务表。

### 6.2 已有完成结果

顶部显示最近一次正式结果：

```text
任务名称
完成时间
总行数
自动匹配数
人工确认数
未匹配数
仍待确认数（如有）
```

提供简洁结果预览和主操作：

```text
[查看完整结果]
[下载 Excel]
```

### 6.3 正在生成/等待前一步

如果最新任务仍在进度监控或人工调整阶段，或结果正在生成：

```text
结果尚未准备完成
当前任务：xxx
当前阶段：xxx
```

根据阶段提供前往“第二步 · 进度监控”或“第三步 · 人工调整”的入口。

### 6.4 尚无任何结果

显示：

```text
尚无可下载结果
请先启动匹配任务并完成必要的人工调整。
```

### 6.5 历史结果

历史列表保留：

- 查看；
- 下载；
- 准确率验收。

但列表不抢占顶部最新结果的视觉重点。

## 7. 业务字典与管理员高级数据

### 7.1 普通业务入口

普通业务导航不再展示“基础数据”。如果业务字典仍有独立维护价值，仅保留：

```text
业务字典
```

业务用户无需理解或预先维护：

```text
集团码目录
文件资产
向量索引
SHA256
Embedding / Index 技术对象
```

### 7.2 业务字典

显示：

```text
字典名称
最新版本
映射条目
更新时间
操作
```

主要操作：

```text
新建业务字典
维护条目
发布新版本
查看历史
```

字典版本用于保持历史任务可追溯，但普通页面不显示 SHA256。

### 7.3 集团码历史版本、文件资产与向量索引

这些对象由平台自动管理，或仅在管理员高级信息中用于兼容历史任务和排障。

处理方式：

- 不作为业务用户创建任务的前置步骤；
- 不与业务字典同级展示；
- 管理员高级信息默认折叠；
- 不删除后端文件、目录版本、索引和诊断 API。

普通业务界面不得显示：

```text
File ID
Index ID
Catalog Version ID
SHA256
embedded_bbq_flat_v2
绝对物理路径
量化算法内部名
```

## 8. 系统设置

### 8.1 页面结构

系统设置按业务管理员能够理解的层级拆分：

```text
账号与权限 | 运行状态 | 高级技术信息
```

默认优先进入“账号与权限”。顶部保持：

```text
[当前身份] [修改我的密码] [刷新状态]
```

### 8.2 账号与权限

默认展示当前账号摘要。管理员额外显示用户管理：

```text
用户名
角色
启用
需改密
更新时间
操作
```

支持：

```text
创建账号
修改角色
启停账号
重置密码
修改自己的密码
```

所有操作使用真实后端接口。

### 8.3 运行状态

优先展示业务可理解的服务健康信息：

```text
平台服务
语义匹配服务
可用匹配索引数量
系统版本
当前账号
业务角色
单批数据安全上限
```

数据目录、索引目录、Token Budget 等不在普通运行状态首屏展示。

### 8.4 高级技术信息

Embedding Provider、Token Budget、模型目录、向量索引、Benchmark、BBQ 等进入“高级技术信息”，默认折叠，仅用于管理员/运维排障。

### 8.5 对齐要求

- Tag 与 Button 高度协调；
- Select/Switch/文本垂直居中；
- 长时间戳使用人类可读格式；
- 控件不得因表格列宽变化发生明显上下错位；
- 1366×768 和 1920×1080 均需检查。

---

## 9. 全局状态设计

每个正式页面都必须设计以下状态：

```text
Loading
正常有数据
空数据
无权限
后端失败
前置步骤未完成
数据生成中
```

禁止：

- 白屏；
- 大面积空白但不给解释；
- 用 0 行表格代替业务空状态；
- 后端失败时仍展示“已完成”；
- 前一步未完成却显示可执行下一步的主按钮。

---

## 10. 前后端接入要求

UI 出现的数据必须真实接入后端。

重点检查：

- 任务草稿；
- Source/Target 上传；
- 字段映射和规则快照；
- 任务启动；
- progress/live-results；
- workbench summary/items/candidates；
- confirm/reject/batch；
- finalize/exports/download；
- 用户、角色、密码和状态；
- 业务字典；
- 后台目录版本、文件与索引能力继续保留。

页面不得通过前端数组伪造“任务、结果、统计值、下载文件”。

## 11. 浏览器最低版本与升级提示

正式最低版本：

```text
Firefox >= 79
Chrome >= 87
```

不满足版本时，在 Vue 主应用加载前显示独立提示页面：

```text
浏览器版本过低
请使用 Firefox ≥79
```

或：

```text
浏览器版本过低
请使用 Chrome ≥87
```

该提示页必须能在 Firefox 47 这类旧浏览器中独立工作，不能依赖 Vue/Element Plus。

## 12. 多 Agent 页面边界

页面级改造应保持：

```text
第一步 · 数据上传: ProfilesView.vue / TaskWorkspace.vue
第二步 · 进度监控: TasksView.vue
第三步 · 人工调整: ReviewView.vue + review.css
第四步 · 输出结果: ResultsView.vue + results.css
业务字典/管理员高级数据: DataView.vue
系统设置: SystemView.vue
```

页面 Agent 默认不修改：

```text
App.vue
router.ts
api.ts
main.ts
styles.css
vite.config.ts
package.json
```

全局 UI 收敛专项可以在明确文件边界后修改 `App.vue`，但不得顺带改动匹配算法或其他 Agent 负责页面。

## 13. UI 验收清单

正式合并前至少验证：

1. 左上角统一为真实“小罡 AI”品牌视觉；
2. 四步导航只出现“第一步 · 数据上传 / 第二步 · 进度监控 / 第三步 · 人工调整 / 第四步 · 输出结果”；
3. 普通导航不再要求用户进入集团码目录或文件资产；
4. “编辑方案”和“创建任务”保持不同语义；
5. 第二步有运行/无运行状态正确；
6. 第三步三种顶部状态正确；
7. 第四步能展示最新结果、预览和真实下载；
8. 业务字典为独立简化入口，技术资产已降级到管理员高级信息；
9. 系统设置默认突出账号、权限与服务状态，高级技术信息默认折叠；
10. 所有页面刷新后仍从后端恢复真实状态；
11. reviewer/viewer 不出现无权执行的有效操作；
12. Firefox <79 / Chrome <87 显示升级提示。

---

## 14. 实现红线

以下任一项视为偏离 v3.1 UI 设计：

1. 用户可见导航重新出现 `STEP 1/2/3/4`、`方案与配置` 或 `匹配计算`；
2. 第一部要求用户先去独立“集团码目录”维护数据才能上传目标 Excel；
3. 第三步只有任务表，没有状态化操作台；
4. 第三步在计算未完成时误导用户可以人工确认；
5. 第四步只有历史任务表，没有最新结果工作台；
6. 最终结果没有突出真实 Excel 下载；
7. 文件资产、向量索引或集团码目录继续作为普通业务一级入口；
8. 普通用户首屏出现大量技术 ID、算法名、SHA256、Embedding/Index 标识或物理路径；
9. 系统设置默认把 Embedding、Token Budget、BBQ、索引和 Benchmark 与账号管理堆在同一层；
10. 页面展示的数据没有真实后端来源；
11. 低版本浏览器直接白屏而不是升级提示；
12. 为修一个页面随意修改其他 Agent 负责的页面或匹配算法。
