# MATERIAL_MATCHER 非技术用户配置体验设计

> 状态：Normative Draft
>
> 本文规定：系统虽然内部采用 Profile、Plugin、Rule Set、Catalog、Join 等技术抽象，但这些概念**不得成为普通业务用户完成配置的前置知识**。默认界面必须以业务语言、向导、自动识别、预览和试跑为主；YAML、插件 ID、表达式等仅在“专家模式”中出现。

---

## 1. 目标用户

默认用户假定为：

- 熟悉本单位物料业务；
- 能看懂 Excel 表头和样例数据；
- 知道“哪个字段更重要”“多少相似度可以接受”；
- **不会写 YAML / Python / SQL，也不需要理解向量数据库、BBQ、Join、Rule Set 等技术术语。**

因此系统的第一原则是：

> 用户配置的是“业务规则”，系统负责把它编译成技术 Profile。

---

## 2. 三层使用模式

### 2.1 向导模式（默认）

面向绝大多数客户实施人员。全程图形化，不显示 YAML。

推荐流程：

```text
1. 上传客户物料样表
2. 上传集团码样表
3. 自动识别表头和字段
4. 确认字段含义
5. 确认分类/物料组路由
6. 配置字段对应关系
7. 调整字段重要程度
8. 调整匹配严格程度
9. 试跑样本
10. 查看命中/疑似/未匹配结果
11. 发布配置
```

### 2.2 高级模式

面向实施顾问，允许设置：

- 多数据源 Join；
- 多 Catalog；
- matcher 类型；
- critical 字段；
- 动态权重；
- 阈值分段；
- 字典和归一化规则；
- BBQ 召回参数。

仍然优先使用表单和可视化编辑器。

### 2.3 专家模式

面向研发/高级实施人员：

- 查看最终 Profile YAML；
- 导入/导出 YAML；
- 查看 Execution Plan；
- 查看插件 ID 和参数；
- 查看配置 SHA-256；
- 诊断配置编译结果。

专家模式默认折叠，不应出现在首次使用路径中。

## 3. 术语翻译规则

UI 不直接暴露底层术语：

| 技术概念 | 普通界面名称 |
|---|---|
| Source | 客户物料数据 |
| Target / Catalog | 集团码数据 |
| Logical Field | 字段含义 |
| Join | 补充数据 / 合并表格 |
| Rule Set | 匹配规则方案 |
| Router | 按物料类型选择规则 |
| Weight | 重要程度 |
| Threshold | 匹配严格程度 |
| Matcher | 比较方式 |
| Dictionary | 同义词 / 别名 |
| Dry Run | 试跑 |
| Profile | 配置方案 |
| Publish | 发布配置 |
| Execution Plan | 实际执行方案 |

专家模式才显示括号中的技术名。

## 4. Excel 导入体验

### 4.1 上传后自动识别

系统应自动检测并给出置信度：

- Sheet；
- 表头所在行；
- 数据开始行；
- 可能的物料号列；
- 可能的名称/规格/型号/厂家/标准/物料组字段；
- 编码列是否存在前导零风险；
- 空值占位符；
- 重复主键；
- 示例值。

界面展示：

```text
系统识别到：
✓ 物料号：MATNR              置信度 99%
✓ 物料名称：ZWLMC            置信度 96%
? 规格：ZXHGG / ZGG          需要确认
! “88”可能为空值占位         建议检查
```

用户只需要“确认 / 修改”，不需要从空白页面开始配置。

### 4.2 字段卡片必须展示样例值

字段名不足以让业务用户判断含义。每个字段卡片至少显示 3~5 个脱敏/抽样值，例如：

```text
字段：ZXHGG
系统猜测：规格型号
样例：
- Φ20×1000
- 0.5mm
- 3240 2×1020×2040
```

### 4.3 前导零保护

编码类字段默认按文本读取。UI 若发现 Excel 将类似 `00001234` 解析成数字，应明确提示并阻止静默丢零。

## 5. 字段对应关系：拖拽而不是写配置

普通用户看到两个字段区：

```text
客户物料字段             集团码字段
[物料名称]  ─────────→  [名称]
[型号]      ─────┐
[规格]      ─────┴────→ [型号规格]
[厂家]      ─────────→  [生产厂家]
```

系统自动生成一对一、一对多、多对一、多对多关系。

每条关系下只显示业务选项：

- 比较方式：自动 / 完全一致 / 相似文本 / 数值规格 / 标准号 / 语义理解；
- 重要程度：低 / 中 / 高 / 很高；
- 必须一致：开关；
- 空值时：忽略该项 / 视为不匹配。

高级模式再显示实际 matcher、weight、critical 等参数。

---

## 6. 权重设置：业务滑块 + 自动归一化

普通用户不应该手工保证权重加起来等于 1。

默认显示：

```text
型号规格     ██████████  很高
生产厂家     ████████    高
物料名称     ██████      中
分类路径     ████        中低
备注         ██          低
```

系统自动转换成数值权重并归一化。

支持“推荐权重”：

- 根据字段完整率；
- 根据字段唯一性；
- 根据已确认样本的区分能力；
- 根据历史模板。

所有自动推荐必须可解释，并允许用户覆盖。

---

## 7. 匹配严格程度：不能只给一个 0.86

普通用户更容易理解风险，而不是内部相似度数学值。

默认提供滑块：

```text
更重覆盖率  ←────────●────────→  更重准确率
              当前：偏严格
```

并实时显示预计影响：

```text
基于当前 500 条试跑样本：
预计自动匹配：61%
建议人工复核：24%
未匹配：15%
已确认样本中的误匹配：0.7%
```

高级模式才显示：

```text
MATCHED > 0.91
REVIEW  0.82 ~ 0.91
UNMATCHED <= 0.82
```

**阈值调整必须基于试跑样本给出结果变化预览，禁止让非技术用户盲调数字。**

---

## 8. 分类 / 物料组路由向导

对于 13 所这类不同大类使用不同集团码模板的情况，普通界面展示：

```text
客户物料类型       使用哪一套集团码数据      匹配方案
元器件             元器件集团码表            元器件方案
复合材料           复合材料集团码表          复合材料方案
金属材料           金属材料集团码表          金属材料方案
```

用户不需要理解 Router / Catalog / Rule Set。

系统还应自动给出分类值分布和未路由值：

```text
已覆盖 98.7% 数据
还有 3 个物料类型未指定规则：A008、A009、其他
```

存在未路由数据时，默认禁止直接发布，除非用户明确配置 fallback。

---

## 9. 多表补充字段：可视化“补充数据”

普通用户不需要写 Join。

界面流程：

1. 点击“添加补充数据”；
2. 上传 MARA/MAKT/其他 Excel；
3. 系统自动建议关联字段，例如 `MATNR ↔ MATNR`；
4. 显示预计匹配率；
5. 用户选择需要补充的字段；
6. 系统检测一对多爆炸风险。

示例提示：

```text
使用“物料号”关联：
主表 100,000 行
可补充 99,421 行（99.42%）
发现 17 个重复物料号，请先处理或选择重复策略。
```

## 10. 同义词配置

采用表格方式：

| 标准写法 | 同义词/别名 | 适用字段 |
|---|---|---|
| 中国电子科技集团 | CETC、中国电科 | 厂家 |
| 不锈钢 | SUS、stainless steel | 材质 |

支持：

- Excel 批量导入；
- 搜索；
- 启用/禁用；
- 冲突检测；
- 立即在试跑样本中查看影响。

---

## 11. 试跑是发布前强制步骤

“保存配置”不等于“立即正式运行”。推荐状态：

```text
草稿 → 校验通过 → 试跑通过 → 已发布
```

试跑默认抽取 100~1000 条，也允许用户上传一批已知正确集团码样本。

结果页重点展示：

- 自动匹配率；
- REVIEW 比例；
- 未匹配比例；
- Top1 / TopN；
- 已知真值准确率；
- 典型错误案例；
- 最容易混淆的字段；
- 阈值变化影响。

用户可以点击任意一行查看“为什么匹配到它”：

```text
型号规格：98 分（很强证据）
厂家：100 分（完全一致）
标准号：100 分（标准化后一致）
名称：84 分
分类：100 分
综合：94.2 分
```

## 12. 错误提示必须可行动

禁止普通界面只显示：

```text
SchemaValidationError
```

应显示：

```text
无法发布：集团码字段尚未指定。

建议：在“集团码数据 → 字段含义”中选择用于输出的集团码列。
[立即去设置]
```

错误分三类：

- **阻止发布**：必须修复；
- **风险提醒**：允许继续，但必须确认；
- **优化建议**：不影响运行。

所有错误均带“定位到配置项”的按钮。

---

## 13. 配置版本与回滚

非技术用户必须可以放心试错。

每次发布生成不可变版本：

```text
元器件匹配方案 v12
发布时间：2026-09-12 14:30
发布人：admin
试跑准确率：98.7%
```

支持：

- 查看版本差异；
- 一键回滚；
- 克隆为新版本；
- 导出“客户配置包”；
- 导入另一台服务器。

底层仍保存 Profile SHA-256，用于审计和复现。

---

## 14. 客户配置包

为了真正实现“换所不改代码”，系统应支持导出：

```text
customer-profile.zip
├── profile.yaml
├── catalogs/
├── mappings/
├── dictionaries/
├── templates/
└── manifest.json
```

新服务器可通过 UI “导入配置包”，自动完成兼容性检查。

这样客户交付可以变成：

```text
同一个 MATERIAL_MATCHER 安装包
+ 不同 customer-profile.zip
```

而不是重新编译程序。

## 15. 首页信息架构

普通管理员登录后建议只看到五个一级入口：

```text
首页
匹配任务
配置向导
数据与索引
系统管理
```

首页卡片：

- 新建匹配任务；
- 新建/复制配置方案；
- 最近任务；
- 当前生效配置；
- 集团码索引状态；
- 临时文件空间；
- 系统健康状态。

YAML、插件、Execution Plan 等放在“系统管理 → 专家工具”。

---

## 16. UI 验收标准

第一版 UI 必须用真实非技术流程验收：

1. 给用户两份从未见过的 Excel；
2. 不提供 YAML 文档；
3. 用户能仅通过界面完成：上传 → 识别 → 映射 → 权重 → 阈值 → 试跑 → 发布；
4. 普通流程中不要求输入任何插件 ID、Python 表达式、SQL 或 YAML；
5. 所有高风险配置在发布前被校验；
6. 用户能回答“为什么这一条匹配成功/失败”；
7. 用户能一键回滚到上一版本。

如果完成一次普通客户配置仍需要研发人员修改文件，则视为该阶段设计未达标。

---

## 17. 第一阶段实现优先级

按非技术用户价值排序：

1. 登录页与首页壳；
2. Excel 上传 + 自动表头/字段识别；
3. 字段含义确认；
4. 字段拖拽映射；
5. 权重滑块与自动归一；
6. 严格度滑块与阈值预览；
7. Dry Run；
8. 发布/版本/回滚；
9. 多 Catalog 路由；
10. 多表 Join 可视化；
11. 专家模式 YAML/Execution Plan。

这套顺序保证系统从第一版开始就是“业务人员可操作的产品”，而不是先做成一套只能由开发人员维护的配置框架。
