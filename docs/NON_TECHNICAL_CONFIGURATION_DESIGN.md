# 物料集团码匹配引擎：非技术用户配置体验设计

> 文档版本：2.2  
> 日期：2026-09-13  
> 状态：Normative  
> 说明：本文只规定“非技术业务人员如何完成配置”。页面层级和路由必须遵守 `OPERATION_UI_DESIGN.md` 与 `API_UI_DEPLOYMENT_CONTRACT.md` 第 44 章，不在本文另建一套菜单体系。

## 1. 目标用户

默认用户：

- 熟悉本单位物料业务；
- 能看懂 Excel 表头和样例数据；
- 知道哪些字段更重要；
- 能判断多少相似度可以接受；
- 不需要会 YAML、Python、SQL；
- 不需要理解向量数据库、单比特量化、插件标识等技术概念。

核心原则：

> 用户配置业务规则，系统负责生成并校验技术配置。

## 2. 与总体 UI 的关系

系统一级导航仍只有：

```text
匹配任务
匹配方案
数据配置
系统设置
```

非技术配置全部从“匹配方案 → 方案配置向导”进入，不新增“配置向导”一级菜单，不建设独立首页。

## 3. 七步配置向导

固定步骤：

```text
1 客户物料
2 集团码数据
3 分类范围
4 字段对应
5 权重与阈值
6 试跑验证
7 发布方案
```

普通用户默认不接触 YAML、插件 ID、表达式、索引算法参数。

## 4. 客户物料导入体验

上传后系统自动识别：

- 工作表；
- 表头所在行；
- 数据开始行；
- 可能的物料号列；
- 可能的名称、规格、型号、厂家、标准、物料组字段；
- 编码列前导零风险；
- 可能的空值占位；
- 重复主键；
- 示例值。

界面必须展示字段样例值，让业务人员“确认/修改”，而不是从空白页面编写技术配置。

编码类字段默认按文本处理。发现可能丢失前导零时必须明确提示，不允许静默转换为数值。

## 5. 字段对应：表格优先

正式开发基线采用**可编辑映射表**，不要求普通用户操作复杂连线画布。

固定列：

```text
客户字段组合
集团字段组合
组合方式
匹配方式
权重
关键字段
操作
```

支持：

- 一对一；
- 一对多；
- 多对一；
- 多对多。

字段组合通过“选择字段 + 标签顺序”实现。

组合方式使用中文业务名称：

- 直接；
- 拼接；
- 第一个有效值；
- 多个比较取最高分。

## 6. 数字权重

不使用“低/中/高/很高”等语言等级。

每个字段关系的权重统一使用：

```text
0 ～ 100 整数
```

含义：

- 0：不参与综合评分；
- 数值越大：该字段对综合结果影响越大；
- 不要求所有权重相加等于 100；
- 系统自动归一化并显示实际占比。

例如：

```text
型号/牌号      100   实际占比 25.0%
规格           100   实际占比 25.0%
技术标准        80   实际占比 20.0%
生产厂家        60   实际占比 15.0%
物料名称        50   实际占比 12.5%
备注            10   实际占比  2.5%
```

系统可以给出推荐值，但推荐值必须显示为数字，并允许用户修改。

## 7. 阈值设置

普通用户同样使用数字，不使用“偏严格/偏宽松”作为唯一设置方式。

界面固定显示：

```text
自动匹配成功阈值  [88]
启用人工确认      [开]
人工确认下限      [75]
显示相似度系数    [1.00]
前N名输出          [5]
```

规则：

```text
原始相似度 > 成功阈值       => 自动匹配
人工确认下限 < 原始相似度 <= 成功阈值 => 待人工确认
原始相似度 <= 人工确认下限   => 未匹配
```

系统应在试跑后辅助展示阈值变化的影响，但不得用模糊滑块替代明确数字。

## 8. 分类范围

业务人员可以选择：

```text
全局匹配
同组严格匹配
分类映射匹配
```

分类映射使用简单表格：

| 客户分类 | 允许匹配的集团分类 |
|---|---|
| 元器件 | 元器件目录中的指定分类 |
| 标准件 | 标准紧固件目录中的指定分类 |

系统应显示未覆盖的客户分类。存在未路由数据时默认阻止发布，除非明确配置回退策略。

## 9. 多表补充数据

普通用户不需要理解数据库 Join。

操作流程：

1. 点击“添加补充数据”；
2. 上传附加表格；
3. 系统推荐关联字段；
4. 显示预计匹配率和重复键风险；
5. 用户确认需要补充的字段；
6. 系统生成关联配置。

出现一对多爆炸风险时必须阻止静默继续。

## 10. 同义词/字典

在“数据配置 → 同义词/字典”中维护。

表格字段：

```text
标准值
别名
适用字段
适用类别
状态
```

支持 Excel 批量导入、搜索、启停和冲突检测。

## 11. 试跑

发布前必须试跑。

默认试跑 100 条，允许扩大样本。

至少显示：

- 自动匹配数量；
- 待人工确认数量；
- 未匹配数量；
- 第一候选分；
- 第二候选分；
- 第一、第二候选分差；
- 关键字段冲突；
- TopN 候选。

“查看候选”必须复用正式任务中的候选对比组件，不开发第二套试跑详情页。

## 12. 错误提示

普通界面不得只显示技术异常名。

错误必须包括：

1. 发生了什么；
2. 哪个配置项有问题；
3. 如何修复；
4. 可以直接跳转到对应步骤的入口。

例如：

```text
无法发布：尚未指定用于输出的集团码字段。
请返回“集团码数据”步骤选择集团码列。
[立即去设置]
```

## 13. 版本与回滚

每次发布生成不可变版本。

用户可以：

- 查看版本；
- 克隆为新草稿；
- 回滚；
- 导出客户配置包；
- 在另一台服务器导入配置包。

已发布版本不能直接覆盖修改。

## 14. 普通模式与专家模式

普通模式是默认模式，只显示业务配置。

专家模式可以额外查看：

- 最终配置文件；
- 插件标识；
- 运行计划；
- 配置摘要值；
- 单比特索引技术参数。

专家模式不得改变普通模式的核心配置语义，也不得形成另一套权重或阈值。

## 15. 验收标准

非技术配置体验至少满足：

1. 给用户两份从未见过的 Excel；
2. 不提供 YAML 文档；
3. 用户能够通过七步向导完成上传、识别、分类范围、字段映射、数字权重、数字阈值、试跑和发布；
4. 普通流程不要求输入插件 ID、Python 表达式、SQL 或 YAML；
5. 所有高风险配置发布前被校验；
6. 用户能够查看“为什么这条匹配到这个候选”；
7. 用户能够回滚上一版本；
8. 换客户时不需要修改前端或后端代码。

如果完成普通客户配置仍然必须由研发人员修改源码或服务器配置文件，则本阶段不算完成。
