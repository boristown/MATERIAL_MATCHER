### 51.8 A007

公开包缺少明确对应的集团目标目录。产品行为必须是：

- 未配置目标目录：不自动匹配；
- 用户配置某个目录或全局目录后：按配置执行；
- 禁止代码中默认把 A007 路由到某一其他类别。

### 51.9 A 与 Z 编码说明

当前公开文件实际出现的是 `A001/A002/...`。

如果客户正式现场使用 `Z001/Z006/...`，通过业务路由配置把其作为另一组代码值即可。

底层不得写：

```python
if code == "A001":
```

或：

```python
if code == "Z001":
```

## 53. 当前 MVP 与本规范的差异核对

以下是对当前实现 PR 的核对结果，开发人员必须明确哪些已有、哪些需要调整。

### 53.1 已经基本符合

当前代码已具备：

- FastAPI B/S 服务；
- 固定 admin 登录；
- 120 MB 普通上传；
- Excel 表头和字段样例识别；
- 配置文档校验；
- Excel/CSV 数据集加载；
- 左关联/内关联；
- 通用转换操作；
- 分类路由基础能力；
- global/strict/mapped 三种物料组策略；
- 字段加权评分；
- 严格 `>` 成功阈值；
- 结果与 TopN Excel；
- Embedded BBQ Flat 原型；
- Target 1-bit / Query signed-int4 近似检索；
- 索引保存/加载；
- Vue 3 + TypeScript + Element Plus；
- 麒麟 V10 安装器骨架；
- 12000~29999 高位随机端口；
- 固定逻辑路径；
- 随机 10 位 admin 密码；
- systemd 自启动。

### 53.2 必须改造

#### 权重接口

当前 MVP 存在前端把权重归一化后再传服务端的做法。

正式版必须改为：

```text
UI 0~100
API 0~100
配置 0~100
内部评分时统一归一化
```

#### 任务执行

当前 MVP 使用 Web 进程后台任务。

正式版必须改为持久化任务队列 + 恢复机制，保证服务重启后任务状态可恢复。

#### 会话

当前 MVP 使用 Bearer Token。

正式版建议切换 HttpOnly Cookie；若保留 Bearer，必须完成 XSS 风险评估并禁止持久化密码。

#### 大文件

当前只支持 120 MB 单请求上传。

正式版必须增加分块上传，以满足百万级集团码文件。

#### 元数据

当前主要使用 JSON/YAML 文件保存状态。

正式版必须引入 SQLite 元数据库，避免并发和崩溃一致性问题。

#### UI

当前单文件页面原型必须拆成路由和组件，并按第 44 章逐页实现。

#### 认证密码

当前 10 位随机密码符合需求，但正式版需确保生成字符集、权限和升级不重置均有自动测试。

#### 服务运行身份

当前安装器未固定独立系统用户。正式版建议加入 `material_matcher` 系统用户并以非 root 运行。

### 53.3 文档已纠正的历史歧义

本版本明确纠正：

- 重要程度不再用“低/中/高/很高”；
- 业务权重统一为 0~100；
- `88` 不再作为全局固定空值；
- A001/A006 不属于底层枚举；
- A002/A003/A005/A007 已纳入业务配置说明；
- REVIEW 状态不填写最终集团码；
- 显示相似度不参与匹配成功判定；
- `retrieval_top_k` 与输出 `TopN` 分离；
- 大文件正式导入不能被 120 MB 限制卡死。

## 55. 最终开发红线

1. **业务代码不得出现客户名称或客户类别的硬编码判断。**
2. **UI、API、配置中的权重统一使用 0～100；仅计算过程内部归一化。**
3. **只有相似度严格高于成功阈值才自动填写集团码。**
4. **待复核状态不得提前填写最终集团码。**
5. **显示分不得影响判定。**
6. **大规模任务不得执行 Source × Target 完整精排。**
7. **正式任务必须可持久化、可恢复。**
8. **所有编码字段必须按字符串处理。**
9. **集团码数据和匹配方案必须版本化、不可变、可追溯。**
10. **所有客户使用同一程序、同一安装路径、同一 UI；客户差异只在业务配置。**

完成以上约束后，本设计书可直接作为开发任务拆分、代码评审和验收依据。
