# 13 所 Z001 / Z006 集团码字段映射草案

> 状态：Draft / 待业务确认
>
> 目的：根据 13 所公开 SAP 样例、集团码公开样例、`ZTMM_MARA` 表结构以及历史仓库资料，整理首版字段映射。该文档是客户 Profile 的实例，不代表核心程序硬编码。

## 1. 样例与代码说明

本次公开样例中 SAP 文件使用 `A001`、`A006`，其业务描述分别为：

- `A001`：元器件
- `A006`：复合材料

当前业务沟通使用生产类型 `Z001`、`Z006`。因此本草案按以下关系整理：

- `Z001`（公开样例别名 `A001`）→ 集团码“元器件”格式
- `Z006`（公开样例别名 `A006`）→ 集团码“复合材料”格式

程序实现时不得把 `A001/Z001`、`A006/Z006` 写死在核心代码中，均由 Profile 的类型别名和路由配置控制。

## 3. Z001（元器件）映射

### 3.1 分类层级

集团元器件表没有重复存储最上层“元器件”，而是从其下一层开始使用“大/中/小/细类”。公开样例中的实际值可以交叉验证以下关系：

| SAP | 集团元器件表 | 结论 |
|---|---|---|
| `ZWLYXT` 一层分类描述 = 元器件 | 文件/规则集身份 | 不参与逐行相似度，可用于路由 |
| `ZECFLT` 二层分类描述 | 清洗后大类 | 明确映射 |
| `ZSCFLT` 三层分类描述 | 清洗后中类 | 明确映射 |
| `ZSCFL2T` 四层分类描述 | 清洗后小类 | 明确映射 |
| `ZWCFLT` 五层分类描述 | 清洗后细类 | 明确映射 |

公开样例中可直接观察到：半导体分立器件、晶体管、双极型晶体管、小功率开关晶体管，以及集成电路、单片集成电路、CMOS/TTL 等层级在两侧一致。

### 3.2 属性字段

| 集团元器件字段 | SAP 字段 | 关系 | 建议用途 |
|---|---|---|---|
| 集团编码 | 无 | Target 主键/输出 | 最终集团码 |
| 特殊说明 | `ZTSSM` | 1:1 | 低权重/解释 |
| 计量单位 | `MEINS`（需 enrich） | 1:1 | 精确/词典标准化 |
| 国产_进口 | `ZGCJK` | 1:1 + 代码词典 | 中低权重 |
| 清洗后大类 | `ZECFLT` | 1:1 | 分类约束/权重 |
| 清洗后中类 | `ZSCFLT` | 1:1 | 分类约束/权重 |
| 清洗后小类 | `ZSCFL2T` | 1:1 | 分类约束/权重 |
| 清洗后细类 | `ZWCFLT` | 1:1 | 分类约束/权重 |
| 清洗后产品名称 | `ZWLMC` | 1:1 | 语义 + 字符规则 |
| 清洗后型号或系列 | `ZXH`，可回退 `ZXHPH` | 多选一 | 型号规则 |
| 清洗后详细型号规格 | `ZXHGG`，可回退 `ZXH` | 多选一 | **高权重** |
| 清洗后质量等级 | `ZZLDJ` | 1:1 | 高精度规则 |
| 清洗后封装形式 | `ZFZXS` | 1:1 | **高权重/冲突约束** |
| 清洗后生产厂家 | `ZSCCJ` | 1:1 | **高权重**，厂家别名词典 |
| 清洗后详细规范号 | `ZXXGF` | 1:1 | 标准号规范化 |
| 清洗后外形尺寸 | `ZWGCC` | 1:1 | 规格/尺寸解析 |
| 清洗后通用规范 | `ZZGF` | 1:1 | 标准号规范化 |
| 国别 | 当前无直接字段 | 派生/缺失 | 可由厂家或额外主数据 enrich；不建议强推断 |
| 保留 | 无 | 忽略 | 不参与匹配 |

### 3.3 Z001 建议匹配组合

元器件不宜只把全部字段拼成一条文本。推荐至少保留以下独立证据：

1. 分类路径：`ZECFLT + ZSCFLT + ZSCFL2T + ZWCFLT` ↔ 大/中/小/细类；
2. 产品名称：`ZWLMC` ↔ 清洗后产品名称；
3. 型号身份：`ZXH + ZXHGG (+ ZXHPH)` ↔ 清洗后型号或系列 + 清洗后详细型号规格；
4. 质量等级：`ZZLDJ` ↔ 清洗后质量等级；
5. 封装：`ZFZXS` ↔ 清洗后封装形式；
6. 厂家：`ZSCCJ` ↔ 清洗后生产厂家；
7. 规范：`ZXXGF + ZZGF` ↔ 清洗后详细规范号 + 清洗后通用规范；
8. 尺寸：`ZWGCC` ↔ 清洗后外形尺寸。

其中型号、封装、厂家、质量等级属于强判别字段；语义向量负责召回，但精排阶段应保留关键字段冲突封顶。

## 4. Z006（复合材料）映射

### 4.1 分类层级

集团复合材料表的分类从“聚合物基复合材料”等开始，同样省略 SAP 的最上层“复合材料”。公开样例可验证：

| SAP | 集团复合材料表 | 结论 |
|---|---|---|
| `ZWLYXT` 一层分类描述 = 复合材料 | 文件/规则集身份 | 用于路由 |
| `ZECFLT` 二层分类描述 | 分类Ⅰ级 | 明确映射 |
| `ZSCFLT` 三层分类描述 | 分类Ⅱ级 | 明确映射 |
| `ZSCFL2T` 四层分类描述 | 分类Ⅲ级 | 明确映射 |
| `ZWCFLT` 五层分类描述 | 分类Ⅳ级 | 明确映射 |

公开样例中“聚合物基复合材料 → 棒材/板材 → 酚醛层压布棒/环氧酚醛玻璃布层压板”等层级在两侧高度一致。

### 4.2 属性字段

| 集团复合材料字段 | SAP 字段 | 关系 | 建议用途 |
|---|---|---|---|
| 集团物资编码 | 无 | Target 主键/输出 | 最终集团码 |
| 分类Ⅰ级 | `ZECFLT` | 1:1 | 分类约束 |
| 分类Ⅱ级 | `ZSCFLT` | 1:1 | 分类约束 |
| 分类Ⅲ级 | `ZSCFL2T` | 1:1 | 分类约束 |
| 分类Ⅳ级 | `ZWCFLT` | 1:1 | 分类约束 |
| 名称 | `ZWLMC` | 1:1 | 语义 + 字符规则 |
| 牌号 | `ZXH`，可回退 `ZXHPH` | 多选一 | **高权重** |
| 状态 | `ZZT`（候选） | 1:1 | 更适合过滤/元数据，不建议高权重 |
| 规格 | `ZXHGG`，可回退 `ZGG` | 多选一 | **高权重**，需要尺寸单位归一化 |
| 采用标准 | `ZCGBZ` 为当前首选；可补充 `ZBZH/ZJSBZ/ZZGF/ZXXGF` | 多来源 | **高权重**，标准号规范化 |
| 特殊说明 | `ZTSSM` | 1:1 | 低权重/解释 |
| 计量单位 | `MEINS`（需 enrich） | 1:1 | 单位词典 |
| 国产_进口 | `ZGCJK` | 1:1 + 代码词典 | 中低权重 |
| 生产厂家 | `ZSCCJ` | 1:1 | 有值时加权，无值动态降权 |
| 保留 | 无 | 忽略 | 不参与匹配 |

公开样例对“采用标准”尤其有价值：SAP `采购标准(ZCGBZ)` 中出现 `GB/T5133-1985`、`GB/T1303.1-1998`、`JB/T56073.26-1999`，集团侧“采用标准”存在对应标准，仅空格/符号格式不同。因此该字段需要标准号归一化，而不应仅做普通语义相似。

### 4.3 Z006 建议匹配组合

1. 分类路径：`ZECFLT + ZSCFLT + ZSCFL2T + ZWCFLT` ↔ 分类Ⅰ~Ⅳ；
2. 名称：`ZWLMC` ↔ 名称；
3. 牌号：`ZXH/ZXHPH` ↔ 牌号；
4. 规格：`ZXHGG/ZGG` ↔ 规格；
5. 标准：`ZCGBZ`（主）+ 其他标准字段（回退） ↔ 采用标准；
6. 国产/进口：`ZGCJK` ↔ 国产_进口；
7. 生产厂家：`ZSCCJ` ↔ 生产厂家。

复合材料的牌号、规格、采用标准应比纯语义描述拥有更高判别优先级。例如 `3240`、`3841` 等牌号相同但厚度/直径不同，不能仅因牌号一致就判定同一集团码。

## 5. 空值和代码归一化

### 5.1 SAP 空值占位

公开 SAP 样例中大量字段使用 `88` 作为疑似空值占位；还出现 `/` 等值。集团样例使用 `<NULL>`、`-`。

首版 Profile 应采用“数据源 + 字段级空值词典”，不要在核心代码里全局写死：

```yaml
normalization:
  source_null_tokens: ["", "88"]
  target_null_tokens: ["", "<NULL>", "-"]
```

`88` 是否在所有字段均代表空值仍需正式数据确认；在确认前，建议允许字段级覆盖。

### 5.2 国产/进口

公开样例显示 SAP `ZGCJK` 使用代码值（至少可见 `10/11`，其他样例还存在 `9`），集团侧使用“国产/进口”文字。`10 -> 国产`、`11 -> 进口` 从公开样例具有较强迹象，但应在正式 Profile 启用前由业务或域值表确认；`9` 暂不推断。

建议实现为词典配置，而不是程序判断：

```yaml
value_maps:
  origin:
    "10": 国产
    "11": 进口
```

## 6. 对通用引擎设计的反向验证

这两种真实格式说明通用引擎至少必须支持：

- 物料类型代码别名和规则集路由；
- Source 顶层分类不直接对应 Target 列，而是作为 Target 文件/规则集身份；
- 分类层级发生一位偏移；
- 一个逻辑字段可以从多个物理字段 `coalesce`；
- 不同类型中“标准”实际落在不同 SAP 字段；
- 字段级空值 token；
- 代码值到业务文本的 value-map；
- 字段缺失时动态权重重归一；
- Target 中完全不存在的字段不应降低总分；
- 同一客户不同物料类型可以使用不同权重与不同关键字段约束。

因此建议 Transform DSL 除 `concat` 外正式支持：

- `coalesce`：按优先顺序取第一个有效字段；
- `best_of`：多个候选字段分别比较，取最高字段相似度；
- `value_map`：代码到标准值映射；
- `nullify`：将配置的占位值转换为空值。

## 7. 当前仍需确认的点

1. 生产环境 `Z001/Z006` 与公开样例 `A001/A006` 是否仅为脱敏代码替换；
2. `ZGCJK` 的完整域值，特别是代码 `9`；
3. SAP 计量单位最终从 `MARA-MEINS`、`ZT13_MATERIAL-MEINS` 还是另一张导出表提供；
4. `88` 是否可以在全部相关字段统一视为空值；
5. 集团侧全量数据是否仍按“元器件/复合材料”等不同模板拆分文件；
6. 最终阈值和字段权重必须在带人工确认结果/已知集团码的样本上校准，不能直接把历史查重阈值照搬到集团码映射。
