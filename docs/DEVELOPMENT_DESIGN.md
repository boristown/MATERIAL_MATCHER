# 物料集团码匹配引擎开发设计书

> 文档版本：2.0（可开发基线）  
> 日期：2026-09-12  
> 文档定位：业务评审、详细设计、前后端开发、测试验收和现场部署的统一入口。  
> 产品名称：**物料集团码匹配引擎**。

本版本把设计细化到可以直接拆分开发任务。完整开发规范由本主文档和以下强制附件共同组成：

- [`API_UI_DEPLOYMENT_CONTRACT.md`](./API_UI_DEPLOYMENT_CONTRACT.md)：核心函数输入输出、HTTP 接口、错误码、UI 页面和交互、安装部署、临时文件、安全、测试验收；
- [`ACCURACY_AND_DELIVERY_BASELINE.md`](./ACCURACY_AND_DELIVERY_BASELINE.md)：13 所公开样例准确性核对、当前 MVP 与正式规范的差异、开发顺序和完成定义；

## 1. 产品目标

系统用于将客户侧物料与集团物料主数据进行批量相似度匹配，输出可信的集团码候选及最终结果。

13 所只是首个客户。底层程序不得绑定任何一家单位、任何固定 Excel 表头、任何固定 SAP 表结构或任何固定物料类别。换客户、换字段、换权重、换阈值、换集团码表时，只允许调整业务配置。

核心红线：

1. 客户差异全部配置化；
2. 物料类别属于业务层，不属于底层固定枚举；
3. 字段权重、阈值、同义词、分类映射均可配置；
4. 只有相似度严格高于成功阈值才填写最终集团码；
5. 待人工复核记录不得提前填写最终集团码；
6. 百万级集团物料必须先召回候选，再做高成本精排；
7. 所有客户使用同一套安装包、同一套逻辑目录、同一套管理界面。

## 2. 总体流程

```text
客户物料数据
    ↓
表格自动识别与字段确认
    ↓
可选多表关联
    ↓
字段映射、拼接、清洗、同义词
    ↓
按业务配置选择物料类别对应的集团码数据
    ↓
单比特向量/关键词/规则高速候选召回
    ↓
字段级相似度计算
    ↓
数字权重综合评分
    ↓
关键字段冲突与业务规则修正
    ↓
阈值判断：自动匹配 / 人工复核 / 未匹配
    ↓
匹配结果 + 前 N 名候选 + 字段级解释
```

## 3. 输入数据

第一阶段必须支持：

- `.xlsx`；
- `.xlsm`（只读取数据，不执行宏）；
- `.csv`；
- 多个表格按配置进行左关联或内关联。

系统不得假定表头在第一行、工作表名称固定、物料号列名固定、集团码列名固定。

所有物料号、集团码、分类码必须按字符串处理，不得转换为整数或浮点数。

配置样表普通上传默认上限 120 MB；正式百万级数据必须支持分块上传，默认总上限 2 GB，可配置。

## 4. 字段匹配

必须支持：

- 一对一；
- 一对多；
- 多对一；
- 多对多。

字段组合方式固定定义为：

- `concat`：按顺序拼接；
- `coalesce`：取第一非空值；
- `best_of`：多个比较结果取最高分。

第一阶段匹配方式：

- 完全一致；
- 清洗后完全一致；
- 包含；
- 字符串模糊相似；
- 关键词相似；
- 数值/尺寸相似；
- 标准号比较；
- 向量语义相似；
- 多算法综合。

任何算法都必须实现统一 `0~1` 字段得分接口。

## 5. 权重与综合分

业务界面、HTTP 接口和配置文件中的字段权重统一使用 `0~100` 整数，不允许前端先除以 100。

默认采用动态权重。对于候选对，只有双方都有有效值且权重大于 0 的字段进入综合分：

```text
raw_score = Σ(field_score × weight) / Σ(weight)
```

若没有任何可比较字段：

```text
raw_score = 0
reason = NO_COMPARABLE_FIELDS
```

关键字段冲突采用配置化封顶，不允许写死某个客户字段。

## 6. 阈值与结果状态

业务界面阈值采用 `0~100` 分。

约束：

```text
0 <= 人工复核下限 < 自动匹配成功阈值 <= 100
```

判定必须严格按：

```text
raw_score > success_threshold / 100
    => MATCHED

review_enabled
且 raw_score > review_threshold / 100
且 raw_score <= success_threshold / 100
    => REVIEW

其他
    => UNMATCHED
```

因此恰好等于成功阈值时不是自动匹配成功。

集团码填写规则：

- `MATCHED`：填写集团码；
- `REVIEW`：集团码留空，只保留候选；
- `UNMATCHED`：集团码留空；
- 人工确认后：`MANUAL_MATCHED`，填写人工确认集团码。

## 7. 显示相似度

默认：

```text
display_score = raw_score × 100
```

可配置显示系数，但它只能改变界面显示，不允许改变自动匹配判定。

## 8. 分类与物料组

引擎仅提供三种通用能力：

- `GLOBAL`：不按物料组过滤；
- `STRICT`：客户物料组与集团物料组严格相同；
- `MAPPED`：一个客户物料组映射一个或多个集团分类。

具体 A001/A002/A003/A005/A006/A007 或 Z001/Z006 只能存在于客户业务配置中。

未配置映射时默认不回退全局搜索，除非业务方案显式开启。

## 9. 多物料类别

同一客户允许不同类别使用完全不同的：

- 集团码目录；
- 字段对应；
- 字段组合；
- 匹配算法；
- 权重；
- 阈值；
- 同义词；
- 分类范围。

路由按优先级匹配，首个命中生效，并必须配置默认行为。

## 10. 单比特向量召回

集团侧目标向量主体采用 1 bit/维压缩；查询侧采用有符号 4 bit 量化。512 维时目标主体为 64 字节/条。

向量召回只负责把正确候选尽量送入精排，不直接决定集团码。

正式接口必须提供真正的批量搜索 `search_batch`，不得在 API 层循环调用单条搜索。

索引版本必须与：

- 集团码数据版本；
- embedding 提供器；
- 维度；
- 索引格式

绑定并可追溯。

## 11. 输出

正式 Excel 至少包含：

1. `任务摘要`；
2. `匹配结果`；
3. `TopN候选`；
4. `人工复核记录`（如存在）。

匹配结果必须保留客户原始字段，并追加状态、最终集团码、内部相似度、显示相似度、方案版本、集团码数据版本等。

TopN 超过单个 Excel Sheet 行数时自动拆分多个 Sheet。

## 12. 核心业务对象

必须版本化：

- 上传文件；
- 集团码目录版本；
- 匹配方案版本；
- 向量索引版本；
- 正式匹配任务；
- 人工复核记录。

正式任务必须固定记录使用的方案版本和集团码目录版本，保证结果可复现。

## 13. 持久化

第一阶段采用：

- SQLite 保存元数据和状态；
- 文件系统保存大数据、索引、模型和结果；
- SQLite 开启 WAL 和外键。

固定元数据库：

```text
/var/lib/material_matcher/meta/material_matcher.db
```

运行中任务状态必须持久化。服务重启后不能永久停留在“运行中”。

## 14. 任务状态

正式状态：

```text
PENDING
PREPARING
RUNNING
EXPORTING
COMPLETED
FAILED
CANCELLING
CANCELLED
RECOVERING
```

进度 `0~100` 单调递增并持久化。

第一阶段同一时刻默认只运行 1 个重型索引/匹配任务，其他排队，以优先保证客户服务器稳定。

## 15. B/S 管理端

前端固定使用 Vue 3 + TypeScript + Element Plus，生产包提前构建成静态资源。

必须提供路由：

```text
/login
/
/tasks
/tasks/:taskId
/profiles
/profiles/new
/profiles/:profileId/edit
/catalogs
/catalogs/:catalogId
/dictionaries
/reviews
/temp-files
/system
```

配置向导固定 7 步：

```text
1 客户物料
2 集团码数据
3 分类范围
4 字段对应
5 权重与阈值
6 试跑验证
7 发布方案
```

权重页面只显示数字，不使用“低/中/高/很高”。

字段权重界面必须同时显示：

- 0~100 数字输入；
- 滑块；
- 自动归一化占比；
- 关键字段设置。

详细 UI 行为见强制附件。

## 16. 登录与安全

系统只保留固定账号：

```text
admin
```

首次安装生成随机 10 位字母数字密码，保存：

```text
/etc/material_matcher/secret/admin_password.env
```

权限必须为 `0600`。

密码不得写入前端包和日志。

## 17. 麒麟 Linux V10 部署

不依赖 Docker。

一键安装：

```bash
sudo ./install.sh
```

所有客户统一逻辑路径：

```text
/opt/material_matcher
/etc/material_matcher
/var/lib/material_matcher
/var/log/material_matcher
```

安装器自动：

- 检测 CPU 架构；
- 找可用空间最大的持久化磁盘；
- 选择 12000~29999 未占用高位端口；
- 安装自包含运行时；
- 安装前端静态文件；
- 安装匹配和向量索引能力；
- 生成 admin 密码；
- 注册 systemd；
- 开机自启；
- 执行 `/api/health/ready` 健康检查。

升级不得重新随机端口或密码。

## 18. 临时文件

临时文件只允许位于：

```text
/var/lib/material_matcher/tmp/
```

所有临时对象必须登记清理信息。清理接口只能按任务/时间/类型清理，禁止前端传入任意服务器路径。

正式方案、集团码数据、正式索引、正式结果不得进入临时清理范围。

## 19. 13 所业务样例

当前公开数据实际包含：

- A001 元器件；
- A002 标准件；
- A003 金属材料；
- A005 非金属材料；
- A006 复合材料；
- A007 物资类其他。

集团侧公开包包含：

- 元器件；
- 标准紧固件；
- 金属材料；
- 非金属材料；
- 复合材料。

公开包没有与 A007 一一对应的独立集团码表，因此 A007 必须由业务配置决定目标范围，不允许底层默认路由。

公开文件中的 A001/A006 与业务人员口头提到的 Z001/Z006 不应由底层做任何特殊处理；正式现场出现哪组代码，就在路由配置中登记哪组代码。

## 20. 开发完成定义

每项功能只有同时满足以下条件才算完成：

1. 代码实现；
2. 单元测试；
3. 配置/API 校验；
4. 中文错误信息；
5. UI（若业务可见）；
6. 日志；
7. 文档；
8. CI 通过。

正式交付前必须用至少三套结构明显不同的客户数据验证“零代码换客户”：单表、多表关联、多目录/多类别三类场景均使用同一程序，只替换配置和数据。
