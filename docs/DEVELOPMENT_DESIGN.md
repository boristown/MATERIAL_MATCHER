# 物料集团码匹配引擎开发设计书

> 文档版本：1.1  
> 日期：2026-09-12  
> 文档定位：面向业务评审与开发实施的统一设计书。  
> 产品名称：**物料集团码匹配引擎**。

## 1. 项目定位

本系统用于将客户侧物料与集团物料主数据进行批量相似度匹配，输出可信的集团码候选及最终匹配结果。

系统不是为某一家单位、某一种表格格式或某一种物料类别编写的一次性程序，而是建设一套可重复部署、可灵活配置的物料集团码匹配引擎。13 所只是首个实际应用单位，后续其他所、其他单位使用时，应尽量做到**不修改程序代码，只调整业务配置**。

核心原则如下：

- 客户差异由配置表达，不写入底层程序。
- 物料类别、字段关系、权重、阈值、同义词、分组规则均属于业务配置。
- 输入表格格式变化，不要求修改程序。
- 集团码表格式变化，不要求修改程序。
- 同一客户内部不同物料类别，可以使用完全不同的字段、权重和匹配方式。
- 匹配失败是正常结果，低置信度情况下不得强行给出集团码。
- 所有匹配结果应可解释、可复核、可追溯。

## 2. 总体业务流程

系统整体流程如下：

```text
客户物料数据
    ↓
表格识别与字段确认
    ↓
字段映射、字段拼接、数据清洗、同义词处理
    ↓
按业务配置选择物料类别对应的集团码数据
    ↓
高速候选召回
    ↓
字段级相似度计算
    ↓
按权重综合评分
    ↓
按阈值判断：匹配成功 / 人工复核 / 未匹配
    ↓
输出匹配结果表 + 最相似前 N 名候选表
```

底层只提供通用能力，不预置“元器件必须这样比”“复合材料必须这样比”等客户业务规则。具体规则由客户配置方案决定。

## 3. 输入数据设计

### 3.1 支持的输入方式

第一阶段重点支持：

- Excel 表格；
- CSV 文件；
- SAP 导出表格；
- 多个 Excel 表格组合后形成统一物料数据。

后续可以继续扩展数据库、接口和其他离线数据格式。

### 3.2 表格格式完全可配置

系统不能假定：

- 表头一定在第一行；
- 工作表名称固定；
- 物料号一定叫某个固定字段名；
- 集团码一定在某个固定列；
- SAP 数据一定只有一张表；
- 集团码数据一定只有一套表头。

配置界面应允许用户确认：

- 使用哪个工作表；
- 表头所在行；
- 哪一列是客户物料号；
- 哪一列是集团码；
- 哪些列参与匹配；
- 哪些列属于分类、型号、规格、厂家、标准等业务信息；
- 空值、特殊占位值如何处理。

### 3.3 支持多表补充

部分客户的完整物料信息可能来自多张 SAP 表或多份导出文件，例如主数据表、基本数据表、描述表和客户自定义表。

系统应支持通过物料号等字段进行配置式关联，形成统一的待匹配数据，而不是在程序中写死某个 SAP 表名。

例如可以通过配置实现：

```text
物料主数据表
    +
物料补充属性表
    +
物料描述表
    ↓
形成统一的客户物料数据
```

## 4. 字段匹配配置

### 4.1 不固定逻辑字段

底层不固定“物料名称、型号、规格、厂家”这些字段必须存在。

客户可以根据自己的数据新增任意业务字段，例如：

- 名称；
- 型号；
- 牌号；
- 规格；
- 材质；
- 质量等级；
- 封装形式；
- 生产厂家；
- 技术标准；
- 表面处理；
- 机械性能；
- 外形尺寸；
- 国产/进口；
- 物料分类；
- 其他客户自定义属性。

这些字段均由配置生成，底层程序不需要认识客户原始字段名。

### 4.2 一对一匹配

一个客户字段与一个集团字段比较。

示例：

```text
客户“生产厂家” ↔ 集团“生产厂家”
```

### 4.3 一对多匹配

一个客户字段，与集团多个字段拼接后的内容比较。

示例：

```text
客户“物料描述”
    ↔
集团“名称 + 型号 + 规格”
```

### 4.4 多对一匹配

客户多个字段拼接后，与集团一个字段比较。

示例：

```text
客户“名称 + 型号 + 规格”
    ↔
集团“完整描述”
```

### 4.5 多对多匹配

客户多个字段拼接后，与集团多个字段拼接后比较。

示例：

```text
客户“名称 + 型号 + 厂家”
    ↔
集团“产品名称 + 详细型号 + 生产厂家”
```

拼接顺序、分隔方式、空字段跳过、去重、优先取值等均由配置控制。

## 5. 字段匹配方式

每组字段关系可以单独选择匹配方式，例如：

- 完全一致；
- 清洗后完全一致；
- 包含关系；
- 字符串模糊相似；
- 关键词相似；
- 数值/尺寸相似；
- 标准号规范化后比较；
- 向量语义相似；
- 多种方式综合。

不同物料类别可以采用不同组合。例如型号和标准号可以更强调精确性，名称可以使用语义相似，规格可以使用数值和文本混合判断。

## 6. 字段权重与相似度调整

### 6.1 字段权重

每个字段关系都可以设置独立权重。

例如某一类物料可以配置：

| 字段 | 重要程度示例 |
|---|---:|
| 型号/牌号 | 很高 |
| 规格 | 很高 |
| 技术标准 | 高 |
| 生产厂家 | 中 |
| 名称 | 中 |
| 备注 | 低 |

普通业务用户在界面中可以使用“低、中、高、很高”设置重要程度，系统内部自动换算为数值并归一化。

### 6.2 缺失字段处理

如果某条物料缺少某个字段，可配置为：

- 缺失字段仍占固定权重；
- 只对双方都有有效值的字段重新分配权重。

默认建议采用第二种方式，避免因为某个客户缺少某类字段而整体降低所有物料得分。

### 6.3 匹配成功阈值

每个客户、每个物料类别都可以单独设置匹配成功阈值。

系统原则：**只有内部相似度严格高于成功阈值，才认为已经找到集团码。**

可设置三段式结果：

- 高于成功阈值：自动匹配成功；
- 位于复核区间：需要人工复核；
- 低于复核阈值：未匹配。

不同客户可以根据风险偏好配置不同的严格程度。

### 6.4 显示相似度系数

内部相似度和界面展示相似度应分开。

客户可以调整显示系数或显示映射，使用户看到的分值更符合业务习惯，但匹配成功判断始终以内部原始得分为准，避免“为了显示好看”改变算法判断。

## 7. 同义词与数据标准化

系统应提供可视化同义词配置，例如：

- 厂家全称与简称；
- 中文名与英文缩写；
- 材料俗称与标准名称；
- 单位换算；
- 标准号书写差异；
- 型号中的空格、横杠、斜杠差异；
- 全角/半角差异；
- 大小写差异。

同义词可以按客户、按物料类别、按字段分别维护。

系统同时支持：

- 去除多余空格；
- 统一标点；
- 统一大小写；
- 统一全角半角；
- 统一尺寸符号；
- 统一标准号格式；
- 统一单位；
- 将 `88`、`-`、空字符串等按客户规则识别为空值。

## 8. 物料组与分类匹配策略

系统至少支持以下三种策略：

### 8.1 同组严格匹配

客户物料只在对应的集团物料组内查找。

适用于客户和集团分类体系能够直接对应的场景。

### 8.2 全局匹配

忽略物料组，在指定集团码数据范围内进行全局匹配。

适用于客户物料组与集团分类体系差异较大，或某一客户物料组对应多个集团分类的场景。

### 8.3 分类映射匹配

客户一个物料组可以映射到集团一个或多个分类，再在映射后的范围内查找。

例如：

```text
客户物料组 A
    ↓
集团分类 1 + 集团分类 2 + 集团分类 3
```

分类映射完全属于业务配置，不进入底层程序。

## 9. 多物料类别配置机制

这是本次修订的重点。

**底层引擎不内置任何具体物料类别。**

13 所当前公开样例中出现以下物料类型：

| 13 所样例代码 | 业务类别 | 当前集团码样例情况 | 处理原则 |
|---|---|---|---|
| A001 | 元器件 | 有独立元器件集团码表 | 通过业务配置选择元器件规则和目标表 |
| A002 | 标准件 | 有标准紧固件集团码表 | 通过业务配置选择标准件规则和目标表 |
| A003 | 金属材料 | 有金属材料集团码表 | 通过业务配置选择金属材料规则和目标表 |
| A005 | 非金属材料 | 有非金属材料集团码表 | 通过业务配置选择非金属材料规则和目标表 |
| A006 | 复合材料 | 有复合材料集团码表 | 通过业务配置选择复合材料规则和目标表 |
| A007 | 物资类其他 | 当前公开包中未提供独立同名集团码表 | 由业务配置决定使用其他目录、全局匹配或暂不自动匹配 |

这些类型**仅是 13 所的首个业务配置示例**，不能成为底层系统固定枚举。

未来其他所可以出现完全不同的类别代码和类别名称，例如 `Z001`、`Z006` 或其他内部编码，均只需在管理界面中新增配置。

### 9.1 不同类别可以使用不同字段

例如：

- 元器件可重点关注：分类、名称、型号、详细型号、质量等级、封装、厂家、规范、外形尺寸等；
- 标准件可重点关注：名称、规格尺寸、材料、表面处理、标准号、机械性能等；
- 金属材料可重点关注：牌号、规格、材料形态、采用标准、厂家、国产/进口等；
- 非金属材料可重点关注：名称、牌号/型号、规格、标准、厂家及其他材料属性；
- 复合材料可重点关注：名称、牌号、规格、采用标准、厂家、状态等；
- 物资类其他不固定字段，由业务人员另行配置。

以上只是业务配置模板，不属于底层算法的固定逻辑。

## 10. 高速向量候选召回

客户侧约十万条物料、集团侧约百万条物料时，不能进行完整的逐条两两比较。

系统采用两阶段方式：

1. 先用高速索引从百万级集团物料中召回少量最可能候选；
2. 再对候选执行完整字段匹配、权重计算和业务规则精排。

### 10.1 单比特向量压缩

集团侧目标向量采用类似 BBQ 的单比特压缩思路，每个向量维度主体只存储 1 比特，用于极限压缩和高速批量筛选。

查询侧保留较高精度，批量查询时通过位运算和处理器快速计数指令进行相似度近似计算。

设计目标：

- 大幅降低百万级向量内存占用；
- 提高批量匹配吞吐量；
- 保证正确集团物料尽可能进入前 N 名候选；
- 最终业务判断仍由高精度字段精排决定。

因此，单比特索引只承担“快速找候选”的职责，不直接决定最终集团码。

## 11. 输出设计

### 11.1 正式匹配结果表

结果表应保留客户原始字段，并增加：

- 匹配状态；
- 最终集团码；
- 内部相似度；
- 展示相似度；
- 匹配方案版本；
- 匹配时间；
- 必要的解释字段。

只有达到成功阈值的记录才填写最终集团码。

### 11.2 最相似前 N 名候选表

无论最终是否达到阈值，都应保留最相似前 N 名候选，便于人工检查。

候选信息至少包含：

- 客户物料号；
- 候选排名；
- 候选集团码；
- 综合相似度；
- 各字段相似度；
- 关键命中项；
- 关键冲突项。

## 12. 非技术用户配置体验

普通客户不应该直接编辑配置文件，也不要求理解底层技术术语。

管理端采用配置向导：

```text
上传客户物料样表
    ↓
系统自动识别表头和字段
    ↓
上传集团码样表
    ↓
系统自动建议字段对应关系
    ↓
业务人员确认或拖拽调整
    ↓
设置字段重要程度
    ↓
设置同义词和分类映射
    ↓
设置匹配严格程度
    ↓
小批量试跑
    ↓
查看匹配率、复核率、未匹配率
    ↓
发布业务配置方案
```

系统应提供“普通模式”和“高级模式”。普通模式只显示业务语言；高级模式才显示更细的算法参数。

## 13. B/S 管理平台

系统采用 B/S 架构，推荐 Vue 构建现代化管理界面。

主要页面包括：

- 登录页；
- 首页；
- 匹配任务；
- 配置向导；
- 业务配置方案管理；
- 同义词和字典管理；
- 集团码数据与索引管理；
- 临时文件管理；
- 系统状态与日志。

系统不建设复杂用户体系，仅使用固定管理员账号 `admin`。

安装时自动生成随机 10 位密码，密码固定保存在：

```text
/etc/material_matcher/secret/admin_password.env
```

## 14. 麒麟 Linux V10 部署

目标服务器为银河麒麟 Linux V10，不依赖 Docker。

要求支持：

- 完全离线安装；
- 一键安装；
- 自带运行时和依赖；
- 自动探测可用空间最大的持久化磁盘；
- 推荐数据存放位置；
- 自动选择未被占用的高位端口；
- 默认优先从 12000～29999 范围选择不常见端口；
- 自动生成管理员密码；
- 自动注册系统服务；
- 自动启动；
- 设置开机自启动；
- 安装结束后自动健康检查。

安装命令保持统一：

```bash
sudo ./install.sh
```

所有客户现场统一使用以下逻辑路径：

```text
/opt/material_matcher          程序
/etc/material_matcher          配置
/var/lib/material_matcher      数据、索引、任务、临时文件
/var/log/material_matcher      日志
```

即使实际最大磁盘挂载点不同，也通过固定逻辑路径统一访问，保证实施手册和运维方式在所有客户现场一致。

## 15. 临时文件管理

上传文件、中间转换文件、试跑缓存等统一作为临时文件管理。

管理端应显示：

- 文件或任务名称；
- 占用空间；
- 创建时间；
- 是否正在使用；
- 是否允许清理。

用户可在界面中选择：

- 清理某个任务临时文件；
- 清理超过指定天数的临时文件；
- 清理全部安全可删除文件。

正式业务配置、集团码主数据、正式索引、模型和正式匹配结果不得被临时文件清理功能误删。

## 16. 13 所首个业务配置建议

13 所当前样例说明，同一个客户内部就已经存在多种不同物料类型和不同集团码表结构，因此应将每个类别配置成独立的业务匹配方案，并由物料类型自动选择。

示意：

```text
13 所客户物料
    ↓
读取“物料类型/一层分类”
    ├─ A001 → 元器件配置 → 元器件集团码表
    ├─ A002 → 标准件配置 → 标准紧固件集团码表
    ├─ A003 → 金属材料配置 → 金属材料集团码表
    ├─ A005 → 非金属材料配置 → 非金属材料集团码表
    ├─ A006 → 复合材料配置 → 复合材料集团码表
    └─ A007 → 物资类其他配置 → 按业务确认的目标范围
```

这里的 `A001～A007` 仅存在于 13 所业务配置中。另一个所如果使用完全不同的物料类型代码，只需要重新配置上述路由，不需要修改底层代码。

## 17. 零代码换客户验收标准

系统正式交付前，应使用至少三套结构明显不同的数据验证以下目标：

- 客户 A 使用单张 Excel；
- 客户 B 使用多张 SAP 导出表关联；
- 客户 C 使用多个不同集团码表和不同物料分类；
- 三个客户使用同一套安装程序和同一套服务程序；
- 只更换数据、字段映射、字典、权重、阈值和业务配置；
- 不修改核心源代码即可运行。

如果新客户提出一种系统从未支持过的数据协议或全新算法，可以增加一次通用能力组件；新增后应可被所有客户复用，不允许开发客户专版分支。

## 18. 评测指标

算法调整不能只依赖主观感觉，应建立人工确认的标准答案集。

至少关注：

- 第一名准确率；
- 前 N 名召回率；
- 自动匹配覆盖率；
- 误匹配率；
- 人工复核率；
- 未匹配率；
- 单条平均耗时；
- 十万级批量任务总耗时；
- 百万级集团码索引占用空间。

## 19. 开发实施优先级

第一阶段形成完整可用产品闭环：

1. Excel 数据上传与自动识别；
2. 字段确认与可视化映射；
3. 一对一、一对多、多对一、多对多字段配置；
4. 字段权重、阈值、显示系数、同义词配置；
5. 按物料分类自动选择业务方案；
6. 小批量试跑；
7. 正式批量任务；
8. 匹配结果和前 N 名候选下载；
9. 业务配置版本管理与回滚；
